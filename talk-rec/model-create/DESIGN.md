# 추억 순간 포착 모델 설계 (v2)

차 안 대화에서 "남길 만한 순간"을 찾아 그 구간의 **음성과 자막, 상황 태그**를 저장하는 온디바이스 모델의 설계다. 수치 중 **추정**이나 **초안**이라고 적은 것은 측정으로 대체해야 한다. 앞선 실험은 [v0.1.0 기록](../docs/v0.1.0.md)과 [RAM 캡처와 한영 혼용](../test/stt/feature2-mixed.md)에, 작업별 기록은 [docs/model-create](../docs/model-create/)에 있다.

## 0. v1에서 바뀐 것과 이유

v1은 발화마다 "이야기 점수"를 매겨 후보 구간의 **텍스트**를 남기는 설계였다. 2026-11-10 중간 점검에서 다음이 확인돼 방향을 바꿨다.

- **실제 차 안 대화는 완결된 이야기가 아니다.** 말이 툭 튀어나오고 주제가 계속 바뀐다. 편집된 유튜브 영상처럼 흐름이 잡힌 대화가 드물어, 텍스트만으로 가치 있는 이야기를 남기기 어렵다.
- **전사는 틀린다.** 텍스트가 곧 결과물이면 전사 오류가 그대로 결과물의 오류가 된다.
- **음성을 저장할 수 있다.** 앱이 `AudioRecord`로 받은 PCM을 보관하고 같은 PCM을 `sendAudio()`로 Pleos STT에 넘기는 경로가 이미 검증돼 있다. 마이크 원본을 파일로 쓰고 다시 재생하는 시험과 양산 차량의 마이크 접근은 아직 확인하지 않았다.

| | v1 | v2 |
| --- | --- | --- |
| 남기는 것 | 이야기가 담긴 텍스트 | 대화 구간의 음성 + 자막(Pleos 전사) + 상황 태그 |
| 판정 단위 | 현재 발화 + 직전 3턴 | 대화 묶음 전체 + 직전 묶음의 끝 |
| 판정 시점 | 발화 직후 | 묶음이 닫힌 뒤 (최대 1~2분 늦음) |
| 모델 출력 | 이야기 점수, 제외 플래그 | 남길지 점수, 상황 태그, 남기면 안 되는 사유 |
| 학습 영상 | LLM이 제목으로 선별 | 사람이 직접 보고 승인한 것만 |

v1의 수집기, 분할·전사, 라벨러 실행기, 평가 지표 계산, 학습 틀은 그대로 쓴다. v1의 발화 단위 라벨과 학습 결과는 쓰지 않는다.

## 1. 목표와 범위

- **목표**: 주행 중 대화를 묶음 단위로 보고 "이 묶음을 남길 것인가"와 "어떤 상황인가"를 판정한다. 남기기로 한 묶음의 음성을 파일로 저장하고 자막과 태그를 붙인다.
- **제약**: 앱 전체 RAM 400MB 이하, CPU 3% 이하 권고. [Pleos 성능 기준](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/app-runtime-environment-resources-guide/app-performance-platform-identify)
- **저장 상한**: 주행 1시간당 최대 10분. 상한을 넘으면 점수가 높은 묶음을 남긴다.
- **범위 밖**: 다이어리 문장 정리와 요약, 목적지 기반 질문 추천, 대화거리 추천. 상황 태그는 그 기능들이 재사용할 수 있게 설계한다.
- **학습 방식**: 지도학습 파인튜닝이다. 사용자의 보관·삭제 피드백으로 임계값을 조정하는 개인화는 출시 이후로 둔다.

## 2. 전제 (확인된 사실)

| 확인된 것 | 설계에 주는 의미 |
| --- | --- |
| 기기 입력은 VAD가 자른 발화다. 무음 1초에 닫고 12초에서 자른다. 화자 구분은 없다. | 학습 데이터도 같은 규칙으로 자른다. |
| `ko-KR` 전사에서 외래어가 빠지거나 한글로 음역된다. | 전사는 판정 단서와 자막으로만 쓴다. 결과물의 본체는 음성이다. |
| 앱이 PCM을 갖고 있으므로 파일로 저장할 수 있다. `sendAudio()`는 ON_DEVICE에서 지원된다. | 최근 음성을 RAM에 굴려 담아 두고, 판정을 통과한 구간만 파일로 쓴다. |
| 고정 MiniLM int8(113MB)은 AVD에서 PSS 약 210MiB, 경량 기준선은 약 54MiB였다. | 판별기는 작아야 한다. 1,400만 파라미터급 인코더가 1순위다. |
| 편집된 유튜브 영상은 실제 주행과 대화 흐름이 다르다. 제목만으로는 영상의 성격을 알 수 없다(외국 영상에 TTS를 붙인 영상이 승인된 사례). | 학습에 쓰는 영상은 사람이 직접 보고 승인한다(§8). |
| 저장한 것은 사용자가 나중에 확인하거나 지운다. | 놓치는 것보다 잘못 남기는 편이 낫다. 재현율 쪽으로 기울이고 저장 상한으로 막는다. |

## 3. 문제 정의

**발화**는 VAD가 자른 한 덩어리의 말이고, **묶음**은 이어지는 발화들의 구간이다. 판정 단위는 묶음이다.

**묶음을 닫는 조건(초안)**: 침묵 20초, 또는 길이 90초, 또는 12턴 중 먼저 오는 것. 수치는 사람이 승인한 무편집 영상의 분포를 보고 확정한다.

```text
입력:  [CLS] 앞문맥(직전 묶음의 마지막 2턴) [SEP] 묶음의 턴1 [SEP] 턴2 [SEP] … [SEP]
       · 최대 320토큰(초안). 넘치면 앞문맥부터 버리고, 그래도 넘치면 묶음의 가운데 턴을 버린다
       · 묶음의 턴만 segment id 1
       + 숫자 단서: 턴 수, 묶음 길이(초), 말한 시간 비율, 턴 간격 중앙값, 직전 침묵 길이
출력:  keep 점수(0~1, 보정됨) + 상황 태그(다중 라벨) + 남기면 안 되는 사유(다중 라벨)
```

**늦은 판정**: 묶음이 닫힌 뒤에 판정하므로 저장은 말이 끝나고 최대 1~2분 뒤에 일어난다. 추억은 나중에 보는 것이어서 문제가 없고, 대신 묶음 전체를 단서로 쓸 수 있다. v1의 "직전 3턴만 보고 즉시 판정"보다 단서가 훨씬 많다.

**저장 구간 조립**은 모델 밖 규칙이 맡는다. keep 점수가 임계값 이상이고 남기면 안 되는 사유가 없는 묶음을 고른다. 이어진 묶음이 연달아 통과하면 하나로 합친다. 저장 범위는 묶음 시작 3초 전부터 끝 2초 뒤까지다(초안). 주행 중 누적 저장 분량이 상한에 닿으면 점수가 낮은 것부터 밀어낸다.

**애매한 묶음**(사람이 보기에도 남길지 갈리는 것)을 남길지는 아직 정하지 않았다. 모델은 연속 점수를 내므로 임계값만 바꾸면 두 정책 모두 가능하다. 애매하다고 라벨된 표본을 모아 본 뒤 정한다(§12).

## 4. 라벨 체계

묶음 하나에 다음을 단다. 기준과 경계 사례는 [rubric.md](rubric.md)에 있다.

| 필드 | 값 | 용도 |
| --- | --- | --- |
| `keep` | 0 남기지 않는다 / 1 애매하다 / 2 남긴다 | 주 판정 |
| `tags` (복수) | `recall` 옛날 얘기 / `fun` 웃음·장난 / `kid` 아이의 말 / `scenery` 풍경·감탄 / `plan` 계획·약속 / `family_news` 가족 소식 / `heart` 고민·속마음 / `song` 노래·흥얼거림 | 회상 화면의 분류, 이후 질문 추천의 재료 |
| `exclude` (복수) | `optout` 기록 거부 / `sensitive` 민감한 내용 / `command` 기기 명령 / `external` 라디오·내비·통화·영상 소리 / `garbled` 전사가 무너져 판단 불가 | 저장 정책. 하나라도 켜지면 저장하지 않는다 |
| `skip` | 참/거짓 | 유튜브에만 있는 방송 멘트·내레이션 묶음. 학습과 평가에서 뺀다 |

- **정책과 점수를 분리한다.** 남길 만하지만 당사자가 남기지 말자고 한 묶음은 `keep=2, exclude=[optout]`이다.
- **`keep=2`에는 태그가 하나 이상 있어야 한다.** `keep=0`에는 태그가 없다. `keep=1`은 태그가 있어도 되고 없어도 된다.
- **기록 거부**는 그 묶음과 직전에 저장한 구간까지 소급해 지운다. 기기 명령과 함께 규칙(패턴)과 모델 출력을 병행한다. 이 둘은 놓치면 안 된다.
- **전사가 조금 틀린 것은 `garbled`가 아니다.** 무슨 상황인지 짐작조차 안 될 때만 단다.

## 5. 온디바이스 구조

```text
AudioRecord ─┬─► PCM 순환 버퍼(최근 3분, RAM)
             └─► VAD(≤12s) ─► Pleos STT(sendAudio, ko-KR) ─► 발화 전사 + 시각
                                   → ① 정규화          학습과 같은 함수
                                   → ② 묶음 조립        침묵·길이·턴 수로 닫음
                                   → ③ 규칙 게이트      호출어·명령·기록 거부 패턴, 미디어 재생 상태
                                   → ④ 인코더 판정      묶음당 1회 → keep, tags, exclude
                                   → ⑤ 저장 구간 조립   병합, 앞뒤 여유, 상한 관리, 소급 삭제
                                   → ⑥ 저장             버퍼에서 잘라 압축 음성 + 자막 + 태그 + 시각·위치 참조
```

- **PCM 순환 버퍼**는 16kHz 모노 16비트로 1분에 약 1.9MB다. 3분이면 약 6MB다. 묶음이 닫히고 판정이 끝날 때까지 해당 구간이 버퍼에 남아 있어야 하므로, 버퍼 길이는 묶음 최대 길이 + 판정 대기 + 여유보다 길어야 한다.
- **저장 파일**은 압축 음성(AAC 또는 Opus, 1분에 0.2~0.5MB 추정)과 자막(발화별 시각과 전사)이다. 앱 전용 저장소에만 쓴다.
- **세션 종료·경로 변경·마이크 중단** 시 버퍼와 열린 묶음을 지운다.
- **n-gram 모델(84kB)은 저하 모드**로 남긴다. 인코더 로드 실패나 메모리 압박 시 인코더를 내리고 묶음 텍스트에 n-gram 판정을 쓴다.
- **인코더는 세션 중에만 로드**한다.

## 6. 모델 후보

| 후보 | 구조 | 파라미터 | int8 파일(추정) | 위치 |
| --- | --- | ---: | ---: | --- |
| S0 | 문자 n-gram 로지스틱 회귀 | — | 약 0.1MB | 기준선·저하 모드 |
| **S1** | **KoELECTRA-small-v3 전체 파인튜닝** + 숫자 단서를 분류 머리에 이어 붙임 | 약 14M (측정) | 약 15MB | **1순위** |
| S2 | 다국어 소형 인코더 + 어휘 가지치기 | 약 34M | 약 35MB | 한영 혼용에서 S1이 뒤질 때만 |
| S3 | 정적 임베딩 + 턴 단위 소형 인코더 | 수 M | 5~8MB | 런타임 비용이 예산을 넘을 때의 대안 |
| 제외 | 소형 생성 LLM | — | 수백 MB | RAM·CPU 권고와 양립하지 않음 |

v1에서 S1 학습은 회당 1~2.5분, 체크포인트는 fp32 기준 53.7MiB였다(측정). 입력이 160토큰에서 320토큰으로 길어지지만 판정 횟수가 발화마다에서 묶음마다로 줄어든다.

## 8. 데이터 설계

### 소스

| 소스 | 역할 | 주의 |
| --- | --- | --- |
| **A. 유튜브 무편집 차 안 대화** — 주력 | 실제에 가까운 대화 흐름. 말이 툭 튀어나오고 주제가 바뀌는 저밀도 대화 | 사람이 승인한 영상만 쓴다. 편집된 여행 브이로그, 진행 멘트가 많은 영상, 내레이션·TTS 영상은 쓰지 않는다 |
| B. 공개 구어 말뭉치 (국립국어원 일상 대화, AI Hub 자유대화·차량 명령어) | 연출 없는 일상 대화와 명령 사례. 전사가 사람 손이라 깨끗하다 | 신청과 내려받기에 사람 손이 필요하다. 확보되면 넣는다 |
| C. LLM 합성 장면 — 보조 | A·B에 없는 것만 채운다. 기록 거부, 기기 명령, 라디오 사연 전달, 최소 대립쌍 | 학습 전용. 평가에 쓰지 않는다. 학습 표본의 15% 이하 |
| D. 팀 자체 주행 녹음 (동의) | 실제 Pleos STT를 통과한 평가셋. 방향이 맞는지 볼 유일한 기준이다 | 학습에 넣지 않는다. 소량(1~2시간)이라도 먼저 확보하기를 권한다 |

기준 영상은 사용자가 고른 세 개다: `IOlxH67P1JM`(아빠와 딸 드라이브 수다), `zn4tDPT4RLQ`(차안에서의 가족 대화), `pkGAxu0g0vQ`(할머니·이모·엄마를 태운 드라이브).

### 수집과 사람 승인

1. **찾기**: 검색어, 채널, 직접 지정한 URL로 메타데이터만 모은다. 검색어는 "무편집", "노컷", "드라이브 수다", "차 안 대화"처럼 편집이 없는 쪽으로 잡는다.
2. **자동 제외**: 길이(3분 미만, 3시간 초과), 방송사·공식 채널, 모음집, 음악·공연, 라이브, 비한국어.
3. **사전 선별**: Claude가 제목·채널·설명으로 명백히 아닌 것을 걸러 사람이 볼 양을 줄인다. 승인 권한은 없다.
4. **내려받기와 전사**: 사전 선별을 통과한 영상의 음성을 받아 전사한다. 말 비중, 한글 비율, 발화 수를 계산해 둔다.
5. **사람 승인**: 로컬 검토 콘솔(웹)에서 사람이 영상을 듣고 **승인 또는 거절과 짧은 코멘트**를 남긴다. 점수는 매기지 않는다. 콘솔은 영상마다 실제 발화가 있는 시각의 재생 링크, 전사 일부, 자동 지표를 보여 준다.
6. **학습 반영**: 사람이 승인한 영상만 묶음 생성과 라벨링, 학습에 들어간다. 사람 판정이 없는 영상은 어떤 분할에도 들어가지 않는다.

판정은 `data/approved.tsv`에 `decided_by`(사람 이름)와 `comment`를 함께 기록한다. 매니페스트 `data/sources.tsv`에는 받은 영상이 예외 없이 남아 학습 데이터 출처가 된다.

### 기기와 같은 단위로 자르기

발화는 v1과 같다. Whisper 단어 타임스탬프로 단어 간격 1.0초 이상에서 닫고 12초에서 자른다. 묶음은 그 발화들을 §3의 닫는 조건으로 묶는다. 같은 경계로 PCM 구간을 잘라 Pleos 왕복(아래)에 쓴다.

### Whisper 전사와 Pleos 전사의 차이

v2에서는 전사가 판정 단서일 뿐이라 위험이 줄었지만, 학습 전사(Whisper)와 실제 입력(Pleos)이 다르다는 사실은 그대로다.

1. **정규화 통일**: 양쪽에서 같은 함수를 쓴다(구현·검증 완료).
2. **Pleos 왕복 세트**: 잘라 둔 PCM을 AVD의 `sendAudio()`로 흘려 Pleos 전사를 모은다. gold 전부와 학습셋 일부가 대상이다.
3. **오류 통계 기반 증강**: 왕복 쌍에서 외래어 탈락, 음역, 단어 탈락 빈도를 뽑아 학습 전사에 같은 확률로 넣는다.
4. **보고 기준**: 최종 수치는 Pleos 전사 기준으로 말한다.

### 라벨링

- **silver**: LLM이 루브릭에 따라 묶음마다 `keep`·`tags`·`exclude`·`skip`과 한 줄 근거를 낸다. 주력은 agy의 Gemini 3.8 Flash(low)다. v1 비교에서 low는 medium과 κ 0.81, Codex luna(high)와 κ 0.71이었고, 발화당 0.8초로 가장 가벼웠다. luna는 gold 표본과 두 라벨러가 엇갈리는 묶음의 재판정에만 쓴다.
- **gold**: 사람이 묶음을 읽고 필요하면 듣고 단다. 1차 300묶음은 두 사람이 겹쳐 달아 사람 간 일치도를 본다. 기준은 κ 0.6 이상이고, 못 미치면 루브릭을 고친다. 2차는 dev와 test 전체다.
- **분할**: 채널 id 해시로 train 70 / dev 15 / test 15. gold를 단 채널은 `data/split-overrides.tsv`에 고정한다.
- **보관**: 원본 음성과 전사는 `.local/`에만 둔다. 저장소에는 매니페스트, 판정, 루브릭, 코드, id와 라벨만 담은 gold를 올린다.

### 규모

시간이 아니라 사람이 승인한 채널 수와 학습 곡선으로 정한다. dev와 test에 각각 채널 10개 이상이 들어가야 한다. 데이터를 25·50·100%로 줄여 학습한 dev 곡선이 아직 오르고 있을 때만 수집을 늘린다.

## 9. 학습 설계

1. **목표**: `keep`은 0·1·2를 0·0.5·1로 편 연속 목표의 BCE, `tags`와 `exclude`는 다중 라벨 BCE다. gold에 silver보다 큰 표본 가중치를 준다.
2. **입력**: §3의 텍스트와 숫자 단서. 숫자 단서는 표준화해 분류 머리에 이어 붙인다. 숫자 단서를 뺀 모델과 비교해 기여를 확인한다.
3. **증강**: Pleos 오류 통계 기반 노이즈, 묶음 경계 흔들기(닫는 조건을 조금 바꿔 다시 묶음), 턴 무작위 탈락.
4. **불균형**: 실제 주행의 "남길 묶음" 비율은 유튜브보다 낮다. 임계값은 "시간당 저장 분량"으로 정한다. D 녹음이 생기면 다시 정한다.
5. **보정·양자화**: dev에서 온도 보정 후 ONNX로 내보내고 int8 동적 양자화를 적용한다.
6. **비교 실험**: 모델(S0·S1) × 앞문맥 유무 × 숫자 단서 유무 × 데이터 규모(25·50·100%). 모든 비교는 시드 3개의 평균과 채널 재표집 구간으로 말한다(도구 완료).

## 10. 평가와 통과 기준

| 구분 | 지표 | 통과 기준 (초안) |
| --- | --- | --- |
| 주 지표 | 사람이 "남긴다"고 한 묶음의 재현율 @ 시간당 저장 분량 | 재현율 0.75 이상 @ 1시간당 10분 이하 |
| 오저장 | 사람이 "남기지 않는다"고 한 묶음이 저장된 분량 | 저장 분량의 30% 이하 |
| 정책 | 기록 거부·기기 명령 묶음이 저장되지 않는 비율 | 0.95 이상 (규칙 병행 포함) |
| 경계 | 저장 구간의 앞뒤가 말 중간에서 잘린 비율 | 사람이 표본을 들어 확인 |
| 태그 | 태그별 F1 | 태그별로 따로 보고 |
| 강건성 | Whisper 전사 대비 Pleos 전사 성능 하락 | 재현율 하락 5%p 이내 |
| 양자화 | int8과 fp32의 PR-AUC 차이 | 1%p 이내 |
| 기기 | 증분 PSS, p95 지연, 평균 CPU, 20분 soak, 저장 파일 재생 | §7 목표 |

D 녹음 전까지 수치는 사람이 승인한 무편집 영상에서 잰 **잠정치**다. 합성 데이터로 낸 수치는 실제 성능으로 말하지 않는다.

## 11. 진행 순서

| 단계 | 내용 | 끝났다고 보는 조건 |
| --- | --- | --- |
| N0 영상 승인 | 검토 콘솔, 수집 기준 개정, 사람 승인 | 사람이 승인한 채널이 30개 이상, dev·test 각 10개 이상 |
| N1 묶음과 라벨 | 묶음 생성, 루브릭 v2, silver 라벨, gold 1차 | 사람 간·사람-LLM κ 0.6 이상 |
| N2 학습·비교 | S0·S1, 앞문맥·숫자 단서·규모 비교 | §10의 오프라인 기준 통과 모델 1개 |
| N3 기기 음성 저장 | 순환 버퍼, 묶음 조립, 파일 저장과 재생 검증 | AVD에서 마이크 원본이 파일로 남고 다시 재생됨 |
| N4 Pleos 왕복 | Pleos 전사 수집, 오류 통계, 증강 | gold 전체의 Pleos 전사 확보 |
| N5 기기 추론 | int8 내보내기, Kotlin 토크나이저, AVD 측정 | §7 목표 통과, Python↔Kotlin 점수 일치 |
| N6 통합 | 판정·저장·소급 삭제·상한 관리, 20분 soak | 누락·오류 0 |
| N7 최종 테스트 | D 녹음, 임계값 재설정, 최종 수치 | D 녹음에서 주 지표 보고 |

N3은 모델과 무관하므로 N0~N2와 병행할 수 있다.

**역할**: 설계·작업 배분·산출물 검수는 Claude, 구현은 Codex(`gpt-6.1-sol`, 기본 effort high, 추론이 많은 작업은 xhigh)가 맡는다. 영상 승인, gold 라벨링, B 말뭉치 확보, D 녹음은 사람이 맡는다. 작업 단위는 [TASKS.md](TASKS.md)에 있다.

## 12. 위험과 결정 사항

| 위험 | 대응 |
| --- | --- |
| 유튜브 대화가 실제 차 안과 다름 | 무편집 영상만, 사람 승인, D 녹음 소량을 먼저 확보 |
| 음성 저장은 텍스트보다 민감함 | 앱 전용 저장소, 기록 거부 소급 삭제, 탑승자 동의 표시, 저장 상한 |
| 마이크 원본의 파일 저장·재생과 양산 차량 마이크 접근이 미확인 | N3에서 AVD로 먼저 검증, 실차는 별도 확인 |
| 단서가 적은 묶음을 놓침 | 늦은 판정, 숫자 단서, 재현율 쪽 임계값 |
| "남길 만하다"의 주관성 | 3단계 라벨, 2인 겹침 라벨링, 사용자 확인 단계 전제 |
| 화자 구분이 없어 라디오·통화와 실제 대화가 섞임 | `external` 라벨과 미디어 재생 상태 신호 병행 |
| 구독형 CLI 라벨러의 한도 | agy low를 주력으로, 한도 오류 시 대기 후 이어 하기(구현 완료) |
| 학습 데이터 저작권 | 모든 영상을 매니페스트에 기록해 출처로 공개, 원문·전사 비배포. 공모전 규정은 제출 전에 확인한다 |

**결정된 것**

- **방향**: 텍스트 이야기가 아니라 음성 구간 + 자막 + 태그를 남긴다. 판정은 묶음이 닫힌 뒤에 한다.
- **태그**: §4의 여덟 가지로 시작한다.
- **저장 상한**: 주행 1시간당 10분.
- **영상 승인**: 학습 전에 사람이 직접 보고 승인한다. 사람은 승인·거절과 짧은 코멘트만 남긴다. 로컬 검토 콘솔을 만든다.
- **라벨러**: agy Gemini 3.8 Flash(low)가 주력, Codex luna(high)는 보조다. API 키는 쓰지 않는다.
- **데이터 규모**: 시간 목표를 두지 않고 채널 수와 학습 곡선으로 정한다.

**결정이 필요한 것**

1. **애매한 묶음(`keep=1`)을 남길지**: 애매하다고 라벨된 표본을 모아 보여 드린 뒤 정한다.
2. **묶음을 닫는 수치**: 승인된 영상의 분포를 보고 확정한다.
3. **B 말뭉치와 D 소량 녹음**: 확보 가능 여부.
