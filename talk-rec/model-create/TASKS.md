# 작업 배분 (v3)

[설계안 v3](DESIGN.md)를 구현 단위로 나눈 문서다. 설계·배분·검수는 Claude, 구현은 Codex가 맡는다. effort는 기본 high이고, 조용히 틀리기 쉬운 작업만 xhigh로 올린다. 끝난 작업의 기록은 [docs/model-create](../docs/model-create/)에 있다.

## 담당

| 담당 | 하는 일 |
| --- | --- |
| Claude | 설계 문서, 루브릭, 생성·판정 지시문, 본보기 장면, 작업 지시문, 산출물 재실행 검수, agy·adb·네트워크가 필요한 실행 |

| 사람 | 평가 음성 확보(녹음·영상 승인), 청취 판정, 합성 훑어보기, 실차 마이크·주행 중 제약 확인 |

## 공통 규약

- **환경**: Python 3.12, `model-create/.venv`. Whisper large-v3는 `.local/hf`, turbo는 `dev-tools/.local/models/whisper-turbo`.
- **보관**: 실제 음성·전사·묶음·예측·체크포인트는 `model-create/.local/`과 기기의 앱 전용 디렉터리에만 둔다. 저장소에는 코드, 매니페스트, 판정(id와 라벨), 루브릭, 지어낸 본보기 장면만 올린다. 실제 전사 글을 저장소·문서·로그·보고에 넣지 않는다.
- **정규화** `normalize(text)`: NFKC → 소문자 → 글자·숫자가 아닌 연속 구간을 공백 하나로 → 양끝 공백 제거. `common/normalize-vectors.json`으로 Python과 기기 코드의 일치를 검증한다.
- **모델 입력 글**: 묶음의 줄을 정규화해 줄바꿈으로 잇는다. 합성과 실제가 **같은 함수**를 쓴다(`demo/trial/data.py`).
- **합성 묶음**: `.local/synth/<이름>/`에 `cards.jsonl`, `scenes.jsonl`, `blocks.jsonl`(망가뜨린 글), `labels.jsonl`(`id, verdict, pattern, boundary, level`), `clean.jsonl`(원본).
- **ASR 결과**: `{"id","config","lines":[{"start","end","text"}],"seconds","avg_logprob","no_speech_prob"}` (`demo/asr/data.py`의 `validate_result`).
- **사람 판정**: [rubric.md](rubric.md) §8 형식.
- **영상 승인** `data/approved.tsv`: `decided_by`가 사람인 `approve`만 평가·참고에 쓴다.
- **작업 기록**: 작업을 끝내기 전에 `talk-rec/docs/model-create/T<번호>-<이름>.md`를 한국어로 쓴다. 무엇을 만들었는지, 실행 방법, 결과 수치, 알아 둘 점을 적는다.
- **작업 방식**: 커밋하지 않는다. Codex 샌드박스에는 네트워크·adb·agy·GPU가 없을 수 있으므로 그 실행은 Claude가 한다. pytest는 `--basetemp .local/<이름> -p no:cacheprovider`로 돌린다. 오류 메시지는 종류와 위치(파일·줄)를 내고, 전사 글은 내지 않는다.
- **모델 내려받기**: safetensors만 받는다. `trust_remote_code`가 필요한 모델은 쓰지 않는다.

## 작업별 내용과 완료 조건

**T50 실제 평가 묶음 파이프라인**
실제 음성에서 사람 판정까지 한 줄로 잇는다. (1) 음성 파일을 16kHz 모노 PCM으로 바꿔 Pleos 일괄 전사에 넣고 ASR 결과 형식으로 모은다. push의 크기 확인 결함과 collect의 형식 불일치를 고친다. (2) Pleos 줄의 시각으로 묶음을 만든다(침묵 20초, 길이 90초, 턴 수 조건 없음). 닫는 조건을 바꿔 가며 묶음 길이·줄 수 분포표를 낸다. (3) 청취 화면을 v3 판정으로 고친다: 음성 재생, `keep`/`none`, `kind`, `unsure`, `policy`, 코멘트. 판정자 이름별로 따로 저장하고 다른 사람의 판정은 보이지 않는다. (4) 두 판정자의 일치도(κ, 불일치 묶음 목록)를 낸다. (5) 출처 단위로 dev/test를 나누고, test 묶음의 판정과 예측은 별도 명령으로만 열린다.
완료: 기존 승인 영상 3개로 전 과정이 돌고, 묶음 수와 분포표를 보고한다. test 잠금을 테스트로 보인다.

**T51 직접 녹음 받아들이기**
휴대폰이나 차에서 녹음한 파일(wav·m4a·mp3)을 받아 출처로 등록하고 T50에 넣는다. 녹음 날짜·탑승자 구성·동의 여부를 매니페스트에 적는다. 파일 이름이나 내용이 저장소에 들어가지 않게 한다.
완료: 표본 파일 하나가 묶음과 청취 화면까지 간다.

**T52 기준선 판정기 v3**
[rubric.md](rubric.md) v3로 판정 지시문을 다시 쓰고(`prompts/judge.md`), 실제 Pleos 묶음을 agy로 판정해 사람과 비교한다. 묶음 7개 안팎을 한 번에 보내고, 오류가 나면 그 배치만 다시 시도한다. 판정을 3회 반복해 판정 자체의 흔들림도 잰다. 결과는 T55의 평가표에 기준선으로 들어간다. `prompts/labeler.md`는 v3 지시문을 가리키게 바꾼다.
완료: 가짜 백엔드 테스트 통과. 실제 실행은 Claude가 한다.

**T53 합성 대량 생성과 다양화**
3,000장 이상을 관문을 통과하게 만든다. (1) "없음"의 내용 다양화: 화제·상황·말투 목록을 늘리고, 같은 화제가 `keep`과 `none` 양쪽에 나오게 한다(예: 여행 얘기가 추억이면 `story`, 예약 절차면 `none`). (2) 지름길 검사에 "글자 n-gram의 합성 내부 정확도"와 "라벨별 상위 n-gram 목록"을 더해, 특정 낱말이 라벨을 누설하는지 본다. (3) 최소 대립쌍: 같은 카드로 `story`판과 `none`판을 함께 만든다. **부정적인 대화 유형**(다툼, 혼내기, 떼쓰기, 험담, 걱정스러운 소식 — 여러 번 주고받지만 `none`)을 패턴과 본보기 장면에 추가하고, 같은 소재의 밝은 판(`keep`)과 짝지어 만든다([rubric.md](rubric.md) §5). 라벨에 `negative` 표시를 남겨 따로 집계한다. (4) 생성 재개, 실패 사유 집계, 중복 제거, 훑어보기 표본 추출. (5) 망가뜨리기 수준 0·1·2를 섞는 비율 옵션.
완료: 카드 3,000장의 카드 단계 검사 통과, 생성 명령과 예상 소요 시간 보고. 실제 생성과 훑어보기는 Claude와 사람이 한다.

**T54 Pleos 오류 프로파일 v2** (xhigh)
사람이 고친 기준 전사를 일부 묶음에 만들어(청취 화면에 전사 고치기 모드), Pleos가 어디서 틀리는지 다시 잰다: 아이 말과 어른 말의 오류율 차이, 짧은 대답 누락률, 겹친 말 처리, 줄이 끊기는 위치. 망가뜨리기 규칙의 어림값을 측정값으로 바꾼다.
완료: 망가뜨린 합성 글과 실제 Pleos 글의 통계를 나란히 보고한다.

**T55 학습·평가 v3** (xhigh)
`demo/trial`을 본 코드로 옮긴다. 모델은 M0(글자 n-gram)와 M1(KoELECTRA-small). 합성 규모별 학습 곡선(400·1,000·3,000·10,000), 실제 dev에서 문턱값 선택, 재현율·없음 걸러 내기·시간당 저장 분량, 합성↔실제 차이, 기준선(Gemini, 전부 남김)을 한 표에 낸다. 시드 3개와 실제 묶음 재표집 구간을 붙인다. test는 별도 명령으로 한 번만 잰다.
완료: 같은 시드에서 재현되고, DESIGN §6의 선택 규칙에 따라 고른 모델과 근거 표를 보고한다.

**T56 정책 규칙과 시험 데이터**
기록 거부·기기 호출·명령 패턴 규칙을 만들고, 합성으로 시험 묶음(거부 표현의 변형, 대화 속에 끼어든 명령 한 줄, 라디오 사연)을 만들어 규칙의 차단율과 오차단율을 잰다.
완료: 차단율 0.95 이상, 일반 대화의 오차단율 보고.

**T57 기기 음성 저장 검증** (xhigh)
`AudioRecord` PCM을 3분 순환 버퍼에 담고, 지정한 구간을 압축 음성 파일로 쓰고, 다시 재생해 확인한다. 같은 PCM이 `sendAudio()`로도 넘어가 전사가 나오는지 본다.
완료: AVD에서 마이크 원본이 파일로 남고 재생되며, 구간 오차와 PSS·CPU를 보고한다.

**T58 내보내기와 양자화**
M0는 가중치 표(해시 또는 어휘 + 계수)로, M1은 ONNX int8로 내보낸다.
완료: PC 원본과 내보낸 모델의 점수 차이를 보고한다.

**T59 기기 추론 이식과 AVD 측정** (xhigh)
정규화, 묶음 조립, n-gram 특징 또는 WordPiece 토크나이저, 추론을 앱 코드로 옮긴다.
완료: 시험 묶음 500개에서 점수가 Python과 일치하고, 증분 PSS·p95 지연·CPU를 보고한다.

**T60 통합과 soak** (xhigh)
판정, 저장 구간 조립, 상한 관리, 기록 거부 소급 삭제, 저하 모드를 넣고 20분 soak를 돌린다.
완료: 20분 동안 누락·오류 0, PSS 최고치와 저장 결과를 보고한다.

**T61 연속 STT 비용 측정**
에뮬레이터에서 실제 차 안 음성을 30분 이상 실시간 속도로 계속 넣으며 앱의 CPU·PSS, STT가 끊기거나 결과가 밀리는 구간, 줄이 나오는 지연을 잰다. 무음 구간에서 STT를 쉬게 하는 방식과 계속 켜 두는 방식을 비교한다.
완료: 두 방식의 CPU·PSS·누락을 표로 보고한다. 모델과 무관하므로 먼저 할 수 있다.

**T62 v1·v2 코드 정리**
쓰지 않는 v1 창·라벨러·gold 도구·발화 단위 학습 코드를 `legacy/`로 옮기거나 지우고, 실패하는 테스트를 정리한다. 설계 문서와 README의 경로를 맞춘다.
완료: 전체 pytest 통과.
