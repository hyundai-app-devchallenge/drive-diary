# 작업 배분 (v3)

[설계안 v3](DESIGN.md)를 구현 단위로 나눈 문서다. 2026-11-13부터는 팀 앱 연동([연동 설계](../docs/app-integration/DESIGN.md))이 먼저이고, v4는 [미래 설계](../docs/future/v4-on-device-summary.md)로 보류했다. 설계·배분·검수는 Claude, 구현은 Codex가 맡는다. effort는 기본 high이고, 조용히 틀리기 쉬운 작업만 xhigh로 올린다. 끝난 작업의 기록은 [docs/model-create](../docs/model-create/)에 있다.

## 담당

| 담당 | 하는 일 |
| --- | --- |
| Claude | 설계 문서, 루브릭, 생성·판정 지시문, 본보기 장면, 작업 지시문, 산출물 재실행 검수, agy·adb·네트워크가 필요한 실행 |
| Codex | 아래 작업의 구현, 테스트, 작업 기록 |
| agy (Gemini 3.8 Flash) | 합성 대화 작성, 실제 Pleos 글의 기준선 판정 |
| 사람 | 평가 영상 승인(YouTube만, 직접 녹음 없음), 청취 판정, 합성 훑어보기, 실차 마이크·주행 중 제약 확인 |

**두 모델**: 앱에는 대화 모델(글로 남길 것/없음 판정, 주)과 소리 모델(웃음·고함·울음, 보조)이 들어간다. 소리 모델은 보류이며 자리만 둔다([DESIGN §6.2](DESIGN.md)). 아래 작업은 따로 적지 않으면 대화 모델 작업이다.

## 공통 규약

- **환경**: Python 3.12, `model-create/.venv`. Whisper large-v3는 `.local/hf`, turbo는 `dev-tools/.local/models/whisper-turbo`.
- **보관**: 실제 음성·전사·묶음·예측·체크포인트는 `model-create/.local/`과 기기의 앱 전용 디렉터리에만 둔다. 저장소에는 코드, 매니페스트, 판정(id와 라벨), 루브릭, 지어낸 본보기 장면만 올린다. 실제 전사 글을 저장소·문서·로그·보고에 넣지 않는다.
- **정규화** `normalize(text)`: NFKC → 소문자 → 글자·숫자가 아닌 연속 구간을 공백 하나로 → 양끝 공백 제거. `common/normalize-vectors.json`으로 Python과 기기 코드의 일치를 검증한다.
- **모델 입력 글**: 묶음의 줄을 정규화해 줄바꿈으로 잇는다. 합성과 실제가 **같은 함수**를 쓴다(`demo/trial/data.py`).
- **합성 묶음**: `.local/synth/<이름>/`에 `cards.jsonl`, `scenes.jsonl`, `blocks.jsonl`(망가뜨린 글), `labels.jsonl`(`id, verdict, pattern, boundary, level`), `clean.jsonl`(원본).
- **ASR 결과**: `{"id","config","lines":[{"start","end","text"}],"seconds","avg_logprob","no_speech_prob"}` (`demo/asr/data.py`의 `validate_result`).
- **사람 판정**: [rubric.md](rubric.md) §8 형식.
- **영상 승인** `data/approved.tsv`: `decided_by`가 사람인 `approve`만 평가·참고에 쓴다.
- **작업 기록**: 작업을 끝내기 전에 `talk-rec/docs/model-create/T<번호>-<이름>.md`를 한국어로 쓴다. 무엇을 만들었는지, 실행 방법, 결과 수치, 알아 둘 점을 적는다.
- **작업 방식**: 커밋하지 않는다. Codex 샌드박스에는 네트워크·adb·agy·GPU가 없을 수 있으므로 그 실행은 Claude가 한다. pytest는 `--basetemp .local/<이름> -p no:cacheprovider`로 돌린다. 오류 메시지는 종류와 위치(파일·줄)를 내고, 전사 글은 내지 않는다.
- **모델 내려받기**: safetensors만 받는다. `trust_remote_code`가 필요한 모델은 쓰지 않는다.

## 작업별 내용과 완료 조건

**T50 실제 평가 묶음 파이프라인** — 끝남. 기록은 [T50](../docs/model-create/T50-real-eval-blocks.md).

**T52 기준선 판정기 v3**
[rubric.md](rubric.md) v3로 판정 지시문을 다시 쓰고(`prompts/judge.md`), 실제 Pleos 묶음을 agy로 판정해 사람과 비교한다. 묶음 7개 안팎을 한 번에 보내고, 오류가 나면 그 배치만 다시 시도한다. 판정을 3회 반복해 판정 자체의 흔들림도 잰다. 결과는 T55의 평가표에 기준선으로 들어간다. `prompts/labeler.md`는 v3 지시문을 가리키게 바꾼다.
완료: 가짜 백엔드 테스트 통과. 실제 실행은 Claude가 한다.

**T53 합성 대량 생성과 다양화**
3,000장 이상을 관문을 통과하게 만든다. (1) "없음"의 내용 다양화: 화제·상황·말투 목록을 늘리고, 같은 화제가 `keep`과 `none` 양쪽에 나오게 한다(예: 여행 얘기가 추억이면 `story`, 예약 절차면 `none`). (2) 지름길 검사에 "글자 n-gram의 합성 내부 정확도"와 "라벨별 상위 n-gram 목록"을 더해, 특정 낱말이 라벨을 누설하는지 본다. (3) 최소 대립쌍: 같은 카드로 `story`판과 `none`판을 함께 만든다. **부정적인 대화 유형**(다툼, 혼내기, 떼쓰기, 험담, 걱정스러운 소식 — 여러 번 주고받지만 `none`)을 패턴과 본보기 장면에 추가하고, 같은 소재의 밝은 판(`keep`)과 짝지어 만든다([rubric.md](rubric.md) §5). 라벨에 `negative` 표시를 남겨 따로 집계한다. (4) 생성 재개, 실패 사유 집계, 중복 제거, 훑어보기 표본 추출. (5) 망가뜨리기 수준 0·1·2를 섞는 비율 옵션.
완료: 카드 3,000장의 카드 단계 검사 통과, 생성 명령과 예상 소요 시간 보고. 실제 생성과 훑어보기는 Claude와 사람이 한다.

**T54 Pleos 오류 프로파일 v2** (xhigh)
사람이 고친 기준 전사를 일부 묶음에 만들어(청취 화면에 전사 고치기 모드), Pleos가 어디서 틀리는지 다시 잰다: 아이 말과 어른 말의 오류율 차이, 짧은 대답 누락률, 겹친 말 처리, 줄이 끊기는 위치. 망가뜨리기 규칙의 어림값을 측정값으로 바꾼다.
완료: 망가뜨린 합성 글과 실제 Pleos 글의 통계를 나란히 보고한다.
v4에서: 사람이 고치는 묶음은 20~30개(dev만). 비슷한 소리로 바뀌는 낱말 쌍, 띄어쓰기 오류, 줄 끊김 위치를 망가뜨리기 함수가 쓸 수 있는 형식으로 낸다. 기준 전사와 Pleos 글에서 지금 M1의 판정이 얼마나 다른지도 잰다.

**T55 학습·평가 v3** (xhigh)
`demo/trial`을 본 코드로 옮긴다. 모델은 M0(글자 n-gram)와 M1(KoELECTRA-small). 합성 규모별 학습 곡선(400·1,000·3,000·10,000), 실제 dev에서 문턱값 선택, 재현율·없음 걸러 내기·시간당 저장 분량, 합성↔실제 차이, 기준선(Gemini, 전부 남김)을 한 표에 낸다. 시드 3개와 실제 묶음 재표집 구간을 붙인다. test는 별도 명령으로 한 번만 잰다.
완료: 같은 시드에서 재현되고, DESIGN §6의 선택 규칙에 따라 고른 모델과 근거 표를 보고한다.

**T56 정책 규칙과 시험 데이터**
기록 거부·기기 호출·명령 패턴 규칙을 만들고, 합성으로 시험 묶음(거부 표현의 변형, 대화 속에 끼어든 명령 한 줄, 라디오 사연)을 만들어 규칙의 차단율과 오차단율을 잰다.
완료: 차단율 0.95 이상, 일반 대화의 오차단율 보고.

**T57 기기 음성 저장 검증** (xhigh)
`AudioRecord` PCM을 3분 순환 버퍼에 담고, 지정한 구간을 압축 음성 파일로 쓰고, 다시 재생해 확인한다. 같은 PCM이 `sendAudio()`로도 넘어가 전사가 나오는지 본다. 이 버퍼는 나중에 소리 모델의 입력도 된다.
완료: AVD에서 마이크 원본이 파일로 남고 재생되며, 구간 오차와 PSS·CPU를 보고한다.

**T58 내보내기와 양자화**
M0는 가중치 표(해시 또는 어휘 + 계수)로, M1은 ONNX int8로 내보낸다.
완료: PC 원본과 내보낸 모델의 점수 차이를 보고한다.

**T59 기기 추론 이식과 AVD 측정** (xhigh)
정규화, 묶음 조립, n-gram 특징 또는 WordPiece 토크나이저, 대화 모델 추론을 앱 코드로 옮긴다. 소리 모델 자리(DESIGN §5 ④b)는 인터페이스만 두고 "취소 안 함"으로 동작하게 한다. Pleos 줄 시각으로 묶음 닫기가 실제로 걸리는지 다시 본다.
완료: 시험 묶음 500개에서 점수가 Python과 일치하고, 증분 PSS·p95 지연·CPU를 보고한다.
v4에서: n-gram 대비책은 싣지 않는다(DESIGN §5). 머리 실행, 토큰 위치 ↔ 줄·구절 대응, 태그·템플릿 규칙(T65)까지 옮긴다. int8 확률은 원본과 다르므로 일치는 판정(keep, 범주, 구절 위치) 기준으로 본다.

**T60 통합과 soak** (xhigh)
판정, 저장 구간 조립, 상한 관리, 기록 거부 소급 삭제, 저하 모드를 넣고 20분 soak를 돌린다.
완료: 20분 동안 누락·오류 0, PSS 최고치와 저장 결과를 보고한다.

**T61 연속 STT 수신 확인** (통합 뒤)
Pleos STT는 앱 밖에서 돌므로 비용 측정은 하지 않는다. AVD에서 주행 규제 뒤에도 STT가 이어지는 것은 60초 세션으로 확인했다(DESIGN §2). 통합한 앱에 실제 차 안 음성을 30분 이상 실시간 속도로 넣으며, STT가 끊기거나 결과가 밀리는 구간, 끊긴 사이에 빠진 말, 다시 요청할 때의 지연을 잰다. 같은 동안 녹음 버퍼에 PCM이 빠짐없이 들어오는지도 본다.
완료: 끊김·누락·지연을 표로 보고한다.

**T63 소리 모델 실제 음성 재시험** (보류)
사람이 승인한 실제 차 안 영상에서 울음·고함·웃음 장면과 하품·기침 같은 헷갈리는 소리를 모아 mn10을 다시 시험한다. 대화 모델이 남길 것으로 고른 묶음에 붙였을 때 정상 묶음을 잘못 취소하는 비율과 부정 묶음을 취소하는 비율을 잰다. 넣기로 하면 ONNX로 내보내 ④b에 연결하고, 두 모델을 함께 돌린 PSS·CPU를 잰다.
완료: DESIGN §6.2의 넣는 조건을 통과하는지 보고한다.

**T58a 탑재 문턱 고침** (low)
`.local/export/m1/threshold.json`의 탑재 문턱을 T55 dev 문턱 0.9573729634284973으로 바꾸고, T58이 고른 0.978은 참고 값으로 남긴다. 해시와 T58 문서를 맞춘다.
완료: int8 + 0.957로 dev 77묶음 판정이 PC 원본과 같음을 다시 확인한다.

**T64 STT 견고성 재학습과 관문** (xhigh)
T54의 측정 오류를 망가뜨리기에 반영하고, 같은 장면의 깨끗한 판과 망가진 판의 판정이 같도록 하는 일관성 손실을 더해 M1을 다시 학습한다(시드 3개, T55와 같은 평가 코드). 지금 M1(int8 + 0.957)과 같은 실제 dev에서 비교한다.
완료: DESIGN §13.2 관문 결과를 보고하고, 통과하면 새 몸통을, 아니면 지금 몸통을 "고정 몸통"으로 지정한다. 기준 전사와 Pleos 글 사이의 판정 차이도 낸다.

**T65 태그·템플릿 규칙** (모델 없음)
고정 태그 목록, 낱말 사전(Pleos 오류를 고려한 매칭), 차량 신호 입력 형식(목적지·목적지 종류·요일·시간대·정차), 템플릿 범주와 범주별 템플릿 30~50개, 빈칸 채우기·조사 맞춤·반복 피하기 규칙을 만든다. 태그 목록과 템플릿 초안은 Claude가 쓰고 사람이 승인한다. Kotlin으로 옮길 수 있게 데이터 파일 + 작은 함수로 둔다.
완료: 지어낸 묶음과 차량 신호로 만든 요약 예시 50개, 실제 dev 남길 것 묶음에서 사람 태그와의 일치(사람 몫 끝난 뒤).

**T66 고정 몸통 위 머리** (xhigh)
템플릿 범주(분류), 구절 고르기(시작·끝 위치), 기록 거부 보조(이진) 머리를 고정 몸통 출력 위에서 학습한다. 범주와 구절의 학습 라벨은 Gemini가 합성 장면에 단다(Claude가 실행). 기록 거부는 T56 시험 묶음을 쓴다. 몸통 출력이 그대로인지(keep 점수 동일) 확인한다.
완료: 실제 dev 남길 것 묶음에서 범주 정확도와 구절 품질(사람 판정), 기록 거부 보조의 합성 차단율과 일반 대화 오차단율, keep 판정 불변.

**T68 Gemini 상한 점검** (Claude 실행)
실제 dev child+family 남길 것 묶음 25개의 Pleos 전사만 Gemini에 주고 범주·태그 3~5개·핵심 구절·한 줄을 쓰게 한다. 사람이 음성을 들으며 항목마다 맞음 / 일부 / 틀림 / 지어냄을 단다. 가능하면 같은 묶음의 깨끗한 전사(Whisper large-v3)로도 해서 Pleos 오류의 몫을 가른다. 전사 글은 `.local/`에만 둔다.
완료: 항목별 비율과, v4가 생성기·구절에 얼마나 기댈지에 대한 판단.

**T67 요약 생성기** (xhigh, 주 경로)
후보 A(KETI ke-t5-small의 어휘를 한국어 위주 약 2만 개로 줄인 판)와 후보 E(고정 M1 몸통 + 새 디코더 2~4층)를 "망가뜨린 묶음 → 한 줄 제목"으로 학습한다(DESIGN §13.4). 제목은 Gemini가 합성 장면에 쓴다(장면에 있는 내용만). safetensors만, `trust_remote_code` 없음. 지어내기 검사 규칙, int8 내보내기, 크기·PC CPU 지연, SentencePiece(A)의 Kotlin 이식 가능성 확인을 포함한다. A·E·대비책(T65·T66)의 한 줄을 실제 dev 남길 것 묶음 30개 안팎에서 나란히 보여 주는 비교 화면을 만든다.
완료: 사람 비교 결과(선호, 지어낸 내용 수), 크기·지연, 고른 후보와 근거. 둘 다 기준을 넘지 못하면 대비책을 주 경로로 한다.

**T62 v1·v2 코드 정리**
쓰지 않는 v1 창·라벨러·gold 도구·발화 단위 학습 코드를 `legacy/`로 옮기거나 지우고, 실패하는 테스트를 정리한다. 설계 문서와 README의 경로를 맞춘다.
완료: 전체 pytest 통과.
