# 작업 배분 (v2)

[설계안 v2](DESIGN.md)를 구현 단위로 나눈 문서다. 설계·배분·검수는 Claude, 구현은 Codex(`gpt-6.1-sol`)가 맡는다. effort는 기본 high이고, 조용히 틀리기 쉬운 작업만 xhigh로 올린다. 끝난 작업의 기록은 [docs/model-create](../docs/model-create/)에 있다.

## 담당

| 담당 | 하는 일 |
| --- | --- |
| Claude | 설계 문서, 루브릭, 라벨러 프롬프트, 합성 장면 명세, 작업 지시문, 산출물 검수, 영상 사전 선별(승인 권한 없음), 모델 선택 판단 |
| Codex | 아래 작업의 구현과 실행 |
| 사람 | 영상 승인(검토 콘솔), gold 라벨링, B 말뭉치 확보, D 녹음, 양산 차량 마이크 확인 |

## 공통 규약

- **환경**: Python 3.12, uv, `model-create/.venv`. `dev-tools/.venv`는 건드리지 않는다. Whisper 모델은 `dev-tools/.local/models/whisper-turbo`를 재사용한다.
- **보관**: 원본 음성, 전사, 묶음, silver 라벨, 체크포인트는 `model-create/.local/`에만 둔다. 저장소에는 코드, 매니페스트, 판정, 루브릭, id와 라벨만 담은 gold 파일을 올린다. 전사 본문을 저장소·로그·보고에 넣지 않는다.
- **정규화** `normalize(text)`: NFKC → 소문자 → 글자·숫자가 아닌 연속 구간을 공백 하나로 → 양끝 공백 제거. `common/normalize-vectors.json`으로 Python과 Kotlin의 일치를 검증한다.
- **발화** `.local/utterances/{source}.jsonl`: `{"source":"yt:VIDEO_ID","utt":17,"start":123.45,"end":129.10,"text":"…","asr":"whisper|human|pleos","speaker":null}` (v1과 같다)
- **묶음** `.local/blocks/{split}.jsonl`: `{"id":"yt:VIDEO_ID@12","source":"yt:VIDEO_ID","split":"train","block":12,"start":301.2,"end":371.9,"gap_before":24.5,"utts":[40,41,…],"turns":["…","…"],"prefix":["…","…"],"features":{"n_turns":9,"seconds":70.7,"speech_share":0.61,"median_gap":0.8,"gap_before":24.5}}`. 닫는 조건의 기본값은 침묵 20초, 길이 90초, 12턴이며 설정값이다. `prefix`는 직전 묶음의 마지막 2턴이고, 직전 묶음과의 간격이 60초를 넘으면 비운다.
- **라벨 v2** `{"id":"yt:VIDEO_ID@12","keep":0,"tags":[],"exclude":[],"skip":false,"labeler":"llm:<백엔드>:<모델>:<effort>|human:<이름>","note":"…"}`. `tags`는 `recall, fun, kid, scenery, plan, family_news, heart, song`, `exclude`는 `optout, sensitive, command, external, garbled`다. `keep` 2에는 `tags`가 하나 이상, `keep` 0에는 `tags`가 없다. `skip`이 참이면 `keep` 0에 빈 배열이다. 기준은 [rubric.md](rubric.md)다.
- **판정** `data/approved.tsv`: `video_id, decision(approve|reject|hold), reason, decided_by, comment`. `decided_by`가 `claude`인 줄은 사전 선별일 뿐이다. 묶음 생성·라벨링·학습에는 **사람이 승인한 영상만** 들어간다.
- **분할**: 채널 id 해시로 train 70 / dev 15 / test 15. `data/split-overrides.tsv`의 고정이 우선한다.
- **작업 기록**: 작업을 끝내기 전에 `talk-rec/docs/model-create/`에 작업 번호로 시작하는 Markdown 파일을 한국어로 쓴다(예: `T20-review-console.md`). 내용은 무엇을 만들었는지, 실행 방법, 결과 수치, 알아 둬야 할 점(함정, 가정, 남은 문제)이다. 이 파일은 파일 영역 제한의 예외다.
- **작업 방식**: 지정된 파일 영역 밖을 고치지 않는다. 커밋하지 않는다. 끝나면 실행한 명령, 결과 수치, 통과하지 못한 항목을 그대로 보고한다. Codex 샌드박스에서는 `codex`·`agy` CLI와 브라우저를 쓸 수 없으므로, 그 부분은 Claude가 샌드박스 밖에서 확인한다.

## 작업별 내용과 완료 조건

**T20 영상 검토 콘솔**
사람이 영상을 듣고 승인·거절과 짧은 코멘트를 남기는 로컬 웹 도구다. 점수 입력은 없다. 영상 카드마다 제목, 채널, 길이, 자동 지표(말 비중, 발화 수, 한글 비율, 방송 멘트 비율), Claude의 사전 선별 의견, 실제 발화가 있는 시각의 유튜브 링크 여러 개, 그 시각 주변의 전사 몇 줄을 보여 준다. 승인 / 거절 / 보류 버튼과 코멘트 칸, 키보드 단축키, 상태별 필터, 진행 표시가 있다. 판정은 `data/approved.tsv`에 사람 이름과 코멘트로 바로 저장한다. 내려받지 않은 후보도 메타데이터만으로 볼 수 있다. 127.0.0.1에만 열고 외부 리소스를 불러오지 않는다.
완료: HTTP로 승인·거절·코멘트를 저장하면 `approved.tsv`가 올바로 바뀌고, 다시 열면 이어서 할 수 있으며, 기존 판정(`decided_by=claude`)은 사전 의견으로만 표시된다.

**T21 수집 기준 개정과 사람 승인 관문**
최소 길이를 8분에서 3분으로 낮춘다. `approved.tsv`에 `comment` 열을 더하고 옮긴다. 사람 승인 여부(`decided_by`가 `claude`가 아닌 `approve`)를 매니페스트에서 조회하는 함수를 두고, `--check`에 "사람 승인 없이 학습 분할에 들어간 영상"을 오류로 넣는다. 사전 선별(`claude`)만 통과한 영상은 내려받기와 전사까지만 허용한다. 검색어를 무편집 차 안 대화 쪽으로 바꾼 새 `queries.txt`로 후보를 찾는다(메타데이터만).
완료: 사람 승인이 없는 영상으로는 묶음이 만들어지지 않는 것을 테스트로 보이고, 새 검색으로 늘어난 후보 수를 보고한다.

**T22 묶음 생성과 스키마 v2**
발화를 침묵·길이·턴 수 조건으로 묶어 공통 규약의 묶음 형식으로 쓴다. 숫자 단서를 계산한다. 사람이 승인한 영상만 대상으로 한다. `common/schema.py`에 묶음과 라벨 v2 검증을 더한다(v1 검증은 남긴다). 토큰 길이 분포와 320토큰 초과 비율을 보고하고, 넘칠 때 자르는 순수 함수(앞문맥부터, 다음은 가운데 턴)를 둔다. 닫는 조건을 바꿔 가며 묶음 길이·턴 수 분포를 비교하는 표를 낸다.
완료: 경계 조건(정확히 20초, 90초, 12턴)과 분할·승인 관문, 자르기 함수의 각 갈래를 테스트로 보이고, 실데이터 분포표를 보고한다.

**T23 라벨러 v2**
[prompts/labeler.md](prompts/labeler.md) v2에 맞춰 묶음 단위로 고친다. 한 호출에 묶음 8개 안팎, 직전 묶음 하나를 문맥으로 겹친다. 검증·재시도·한도 대기·이어 하기는 그대로 쓴다. `keep=1`과 "기준 불명확" 항목을 따로 모은다. 비교 명령을 `keep≥2` 이진 κ, `keep` 0~2 가중 κ, 태그별 일치로 고친다. v1 출력 디렉터리는 건드리지 않는다.
완료: fake 백엔드 테스트 통과. 실제 실행은 Claude가 샌드박스 밖에서 한다.

**T24 gold 도구 v2**
묶음 하나를 화면에 보여 주고 `keep` 0·1·2, 태그, 제외 사유, 방송 멘트, 메모를 단다. 묶음 시작 시각의 유튜브 링크를 보여 준다. 저장 형식은 라벨 v2다. 일치도 스크립트를 v2 필드로 고친다.
완료: 묶음 하나를 HTTP로 라벨링해 id와 라벨만 저장되고, 제약 위반을 서버가 거절한다.

**T25 평가 하네스 v2**
묶음 단위 지표를 낸다. `keep≥2` PR-AUC, 저장 시뮬레이션(임계값, 이어진 묶음 병합, 앞뒤 여유, 시간당 10분 상한에서 점수순 선택), 시간당 저장 분량 대비 재현율 곡선, 저장 분량 중 `keep=0` 비율, 제외 사유별 유출률, 태그별 F1, 슬라이스별 표. `keep=1`을 양성·음성·제외로 볼 때의 세 가지 결과를 나란히 낸다.
완료: 손으로 계산한 예제에서 모든 지표가 기대값과 일치한다.

**T26 학습 v2** (xhigh)
입력을 묶음(앞문맥 + 턴들 + 숫자 단서)으로, 목표를 `keep`·`tags`·`exclude`로 바꾼다. 비교 실험은 S0 대 S1, 앞문맥 유무, 숫자 단서 유무, 데이터 25·50·100%다. 시드 3개와 채널 재표집 구간은 T11b의 도구를 쓴다.
완료: T25 하네스로 비교표를 내고 같은 시드에서 재현된다.

**T27 합성 장면 생성**
유튜브에 없는 묶음을 만든다. 기록 거부, 기기 명령, 라디오·내비 음성, 최소 대립쌍. Claude가 명세를 쓴다.
완료: 명세의 종류별 목표 개수를 채우고 중복 제거 후 분포를 보고한다.

**T28 기기 음성 저장 검증** (xhigh)
검증 앱에 새 모드를 넣는다. `AudioRecord` PCM을 3분 순환 버퍼에 담고, 지정한 구간을 압축 음성 파일로 쓰고, 그 파일을 다시 재생해 확인한다. 같은 PCM이 `sendAudio()`로도 넘어가 전사가 나오는지 본다. 버퍼의 PSS 증가와 압축의 CPU 비용을 잰다.
완료: AVD에서 마이크 원본이 파일로 남고 재생되며, 파일 길이와 요청 구간의 오차, PSS·CPU 수치를 보고한다.

**T29 Pleos 왕복 수집** (xhigh)
앱 전용 디렉터리의 PCM 구간을 차례로 `sendAudio()`에 넣고 id와 최종 전사를 TSV로 쓰는 모드를 넣는다. 중단 후 이어 하기와 구간당 시간 제한을 둔다. 전사 본문을 logcat에 남기지 않는다.
완료: 구간 200개가 누락·중복 없이 처리되고, 시간당 처리량과 빈 전사 비율을 보고한다.

**T30 ASR 오류 통계와 증강** (xhigh)
같은 구간의 Whisper 전사와 Pleos 전사를 정렬해 외래어 탈락, 음역, 단어 탈락 빈도를 내고, 그 확률로 동작하는 증강기를 만든다.
완료: 증강한 Whisper 전사와 실제 Pleos 전사의 오류 분포를 나란히 보고한다.

**T31 ONNX 내보내기와 양자화**
고정 길이 입력과 숫자 단서 입력으로 내보내고 int8 동적 양자화를 적용한다.
완료: fp32 PyTorch, fp32 ONNX, int8 ONNX의 점수 차이와 PR-AUC 차이를 보고한다.

**T32 기기 토크나이저·추론과 AVD 측정** (xhigh)
WordPiece 토크나이저, 정규화, 묶음 조립, 숫자 단서 계산을 앱 코드로 옮기고 ONNX Runtime으로 추론한다.
완료: 테스트 묶음 500개에서 토큰 id와 숫자 단서가 Python과 일치하고, 증분 PSS·p95 지연·CPU를 보고한다.

**T33 프로브 통합과 soak** (xhigh)
판정, 저장 구간 조립, 상한 관리, 기록 거부 소급 삭제, 저하 모드를 넣고 20분 soak를 돌린다.
완료: 20분 동안 누락·오류 0, PSS 최고치와 저장 결과를 보고한다.

**T34 공개 말뭉치 변환기**
확보된 말뭉치를 발화 형식으로 바꾼다. 화자 단위로 분할한다.
완료: 말뭉치별 발화 수와 화자 수를 보고한다.
