# 조용할 때만 건네는 대화 질문: 기획

2026-11-14 초안. 기획서 ③ "조용할 때만 건네는 대화 질문"을 실제로 만들 수 있는 규칙으로 옮긴 문서다. 기술 설계는 [DESIGN.md](DESIGN.md)에 있다.

## 1. 한 줄 정의

차 안이 오래 조용할 때만 화면에 잠깐 "질문 하나 해도 될까요?"를 띄우고, 목소리로 받아 주면 Pleos TTS로 여행지·날씨·동행 관계에 맞는 가벼운 질문을 하나 건넨다.

## 2. 기획서 원문과 이번에 정한 것

| 기획서 원문 | 이번에 정한 것 |
| --- | --- |
| 대화가 이어지는 동안에는 끼어들지 않는다 | 말소리가 있으면 조용함 시간을 0부터 다시 잰다. 대화 **내용**은 시점 판단에 쓰지 않는다 |
| 말소리 유무와 목적지까지 남은 시간으로 시점을 판단 | 조용함 시간(PCM 음량 + STT 결과 수신 시각), 여행 경과 시간, 내비의 남은 시간을 쓴다(§4) |
| 작은 음성 안내와 화면 알림으로 "혹시 다들 자고 있나요?" 확인 | **확인은 화면에만 잠깐 띄운다. 소리를 내지 않는다.** 자는 사람을 깨우지 않는 쪽을 택했다. 문구는 기획서 문구를 쓴다 |
| 반응이 없으면 그 여행에서는 먼저 묻지 않는다 | 그대로. 단, 정차 중 화면 버튼이나 디버그 명령으로 직접 부르는 질문은 된다 |
| "아니요" 같은 반응이 오면 가벼운 질문으로 대화를 다시 연다 | 수락 반응을 들으면 **Pleos 기기 안 TTS로 질문을 읽고** 같은 질문을 화면에도 띄운다 |
| 여행지나 동행 관계에 맞는 질문 | 목적지·지금 지나는 지역·날씨·시간대·남은 시간·관계(가족/연인/친구)로 Cloudflare Workers AI가 만든다. 실패하면 앱 안 질문 목록(`QuestionBank`)을 쓴다 |
| (원문에 없음) | **질문에 대한 대답은 녹음·기록하지 않는다.** 빼는 시간은 설정에서 고른다(§6) |

## 3. 사용자 흐름

```text
대화 중 ─────────────► (끼어들지 않음)
   │ 말소리가 멈춤
   ▼
조용함이 이어짐 (기본 8분)  ── 그사이 질문을 미리 만들어 둠
   │ 조건이 모두 맞으면 (§4)
   ▼
Q01 화면 확인 (소리 없음, 10초)
   "혹시 다들 자고 있나요?  깨어 있다면 ‘아니, 안 자’라고 말해 주세요"
   ├─ 수락 ("아니, 안 자", "응", "물어봐", "좋아" …) ──► Q02: TTS로 질문 + 화면 질문 카드
   ├─ 거절 ("자고 있어", "나중에", "질문 그만" …) ──► 이번 여행은 먼저 묻지 않음
   ├─ 다른 말소리 (이미 대화가 다시 시작됨) ──────► 조용히 물러남, 질문 안 함
   └─ 반응 없음 ─────────────────────────────► 이번 여행은 먼저 묻지 않음 (기획서 원문)
Q02 뒤: 설정한 시간(기본 90초) 동안 녹음·기록하지 않음 → 쉬는 시간(20분) → 다시 듣기
```

화면은 팀 앱 v3의 Q01 `QuietCheckScreen`, Q02 `SilenceQuestionScreen`, B01 `ListeningScreen`과 `B01_QUIET`(먼저 묻지 않을게요)를 쓴다. 문구는 v3에 이미 있다. Q01의 "운전석 스피커로 작게 물어봤어요" 줄만 "화면으로만 여쭤봐요"로 바꾼다.

## 4. 언제 묻나 (기본값, 디버그에서 바꿀 수 있음)

모두 맞을 때만 Q01을 띄운다.

| 조건 | 기본값 | 이유 |
| --- | --- | --- |
| 조용함 시간 | 8분 이상 | 짧은 대화 쉼과 구분. 기획서의 "오래 조용해지면" |
| 여행 시작 뒤 | 10분 이상 | 출발 직후는 원래 정신없다 |
| 목적지까지 남은 시간 | 15분 이상 | 곧 도착하면 대화를 열 의미가 작다. 내비 목적지가 없으면 이 조건은 건너뛴다 |
| 직전 질문 뒤 | 20분 이상 | 자주 묻지 않는다 |
| 여행당 질문 수 | 3번까지 | 귀찮지 않게 |
| 녹음 상태 | On (상시 캡처 동의 + 마이크 켜짐) | 말소리를 들을 수 없으면 조용함도 알 수 없다. 멈춤·녹음 없음 여행에서는 묻지 않는다 |
| 마이크 입력 | 쓸 수 있음 | Gleo가 마이크를 잡아 앱 입력이 무음 처리된 구간은 조용함으로 세지 않는다 |
| 외부 AI 동의 | 있으면 AI 질문, 없으면 앱 안 질문 목록 | 요약 동의와 같은 하나의 동의(§10-3) |

"말소리 있음"은 대화 기록이 쓰는 것과 같은 판단이다: 100ms PCM 음량이 문턱(140) 이상이거나 STT 확정 결과가 들어오면 말소리로 본다. 음악·라디오도 말소리로 잡힐 수 있다. 그때는 묻지 않는 쪽으로 틀리므로 그대로 둔다.

## 5. 반응 듣기

- Q01을 띄운 뒤 10초 동안 들어온 STT 확정 결과만 본다. 글은 **그 자리에서 수락/거절/기타로 나누고 버린다**. 저장·로그·외부 전송 없음.
- 수락: 아니/안 자/안자/깨어 있/응/어/네/좋아/물어봐/해 줘/뭔데 등.
- 거절: 자/잔다/쉿/나중에/됐어/괜찮아/질문 그만/하지 마 등. "안 자"가 거절의 "자"로 잡히지 않게 수락을 먼저 본다.
- 말소리는 있었는데 STT 결과가 없으면 "기타"로 본다(대화가 다시 시작됐다고 본다).
- 차량 Gleo 명령("글레오, 동반차 질문해 줘")은 이번 범위 밖이다. 스키마 함수 상한(3개)과 실제 Gleo 동작 미확인([Gleo 시험](../gleo/gleo-voice-test.md)) 때문이다.

## 6. 녹음·기록하지 않는 것

- 늘 빼는 것(설정과 상관없음): Q01 반응, TTS가 읽는 질문 소리.
- **질문 뒤 녹음하지 않는 시간은 설정에서 고른다** (2026-11-14 결정). 이 시간 안에 시작된 대화 묶음은 저장하지 않는다. 판정도, 외부 요약도 하지 않는다.

| 설정값 | 뜻 |
| --- | --- |
| 빼지 않음 | 질문 소리만 빼고, 대답부터 평소 대화 기록 규칙을 따른다 |
| 30초 / 60초 / **90초 (기본)** / 3분 / 5분 | 질문을 다 읽은 뒤 그 시간 동안 시작된 대화를 남기지 않는다 |

- 시간이 끝난 뒤 이어지는 대화는 평소 대화 기록 규칙을 따른다.
- 남기는 것은 "몇 시에 어떤 질문을 건넸다"뿐이다. 팀 앱이 이미 질문을 `Memory(type=QUESTION)`로 저장하고 "지금까지 나눈 대화"에 보여 준다.
- 설정은 정차 중에만 바꿀 수 있다. 질문을 읽기 시작할 때의 값을 그 질문에 쓰고, 도중에 바꿔도 다음 질문부터 적용한다.
- 지금 팀 앱에는 사용자 설정 화면이 없어서, 처음에는 debug의 설정 화면에 둔다. 사용자 설정 화면이 생기면 같은 저장 값을 그 화면으로 옮긴다(DESIGN §7.2).

## 7. 질문 내용

- 길이 40자 이하, 한 문장, 물음 하나. 모두가 대답할 수 있는 열린 질문.
- 재료: 목적지 이름, 지금 지나는 지역(시·구 정도), 날씨(지금·도착지), 시간대, 남은 시간, 관계, 이번 여행에서 이미 한 질문.
- 관계는 지금 **가족으로 가정**한다(아이가 함께 탄 가족 여행). 질문도 아이와 어른이 함께 대답할 수 있는 쪽으로 만든다.
- 하지 않는 것: 사람 이름, 운전자에게 화면을 보거나 조작하라는 말, 위험하거나 민감한 화제(건강, 돈, 정치, 다툼), 대화 기록 내용 언급. 운전자 혼자만 대답할 수 있는 질문도 피한다.
- 예 (지어낸 것): "강릉 바다에 도착하면 제일 먼저 뭐 하고 싶어?", "밖에 비가 오는데, 비 오는 날 하면 좋은 거 하나씩 말해 볼까?", "도착까지 40분 남았는데, 오늘 저녁은 뭐 먹을까?"
- 대화 기록 내용은 질문을 만드는 데 쓰지 않는다. 전사 글이 질문 기능 쪽으로 넘어가지 않는다.

## 8. 주행 중 화면 원칙

- Q01·Q02 알림은 큰 글자 한 줄 + 말로 하는 예시만. 누를 필요가 없다.
- Q01은 10초 뒤, Q02는 TTS가 끝나고 15초 뒤 저절로 사라져 B01/S05로 돌아간다.
- 소리: Q01은 소리 없음. Q02는 TTS만, 효과음 없음.
- 주행 중 글 노출 규정은 대화 기록과 같은 확인 항목이다([연동 설계 §12](../app-integration/DESIGN.md)).

## 9. 디버그 앱에서 할 수 있어야 하는 것

- **지금 위치로 질문 강제 생성**: 조용함 조건을 무시하고, 현재 위치·목적지·날씨를 모아 바로 질문을 만든다. 보낸 맥락 JSON, 받은 JSON, 검증 결과, 걸린 시간을 본다.
- 위치 덮어쓰기: 에뮬레이터는 위치가 고정이라 미리 정한 장소(서울역, 강릉 경포해변, 제주공항)나 직접 입력한 좌표로 바꿔 본다.
- TTS 읽기 시험: 만든 질문을 기기 안 TTS로 읽고 이벤트(준비/시작/끝/오류)와 걸린 시간을 본다.
- 흐름 시험: "조용함 흉내"로 기다림 없이 Q01을 띄우고, 반응 글을 직접 넣어 수락/거절/무반응 분기를 본다. 시간 기본값을 짧게(예: 조용함 30초) 바꾼다.
- 상태 기록: 듣기 → 후보 → 확인 → 질문 → 쉬는 시간 전이를 화면에 보인다. 전사 글은 보이지 않는다.

5. ~~동행 관계~~ **정함 (2026-11-14)**: 지금은 **가족으로 가정**한다. 팀 앱 `Trip`에 관계 칸이 없으므로(`companions`는 이름 목록) 관계 값은 상수 "가족"으로 두고, 나중에 여행 설정의 `selectedCompanion`(가족/연인/친구)을 저장하게 되면 그 값으로 바꾼다.
