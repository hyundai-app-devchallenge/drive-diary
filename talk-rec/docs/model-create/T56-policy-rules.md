## 규칙과 반환 계약

설계 근거는 `DESIGN.md` §3·§4·§5·§10, `rubric.md` §2·§7, `TASKS.md` T56이다. `demo/trial/data.py::input_text`는 문자열이나 `text` 필드가 있는 줄의 앞뒤 공백을 제거하고 줄바꿈으로 잇는다. 게이트도 같은 형태의 줄 목록을 받으며, 정규화는 학습 공통 함수 `common.normalize.normalize`를 직접 호출한다. 정규화 후 매칭 전용 복사본에서 공백을 제거한다. 모델에 넘길 원래 줄을 변경하거나 화자·시각·정답을 매칭에 쓰지 않는다.

```python
from policy import gate, AppSignals

result = gate(["어제 바다에서 놀았지", "볼륨 올려", "조개도 찾았어"])
# {"block": "allow", "drop_lines": [1], "retro_delete": False,
#  "reasons": ["command.volume"]}
```

`block`은 `allow` 또는 `block`이다. `drop_lines`는 **원래 입력 기준 0부터 시작하는 줄 번호**를 중복 없이 정렬한 목록이다. `reasons`는 발화 원문이 없는 규칙 ID다. `retro_delete`는 직전 저장 구간 삭제 요청이다. 함수는 파일·기기·세션을 변경하지 않는다.

1. `optout`: 한 줄 또는 이어진 조각에서 기록 거부가 나오면 대화 비중과 관계없이 묶음 전체를 막고 `retro_delete=True`를 반환한다. 차단한 묶음의 모든 줄을 `drop_lines`에 넣는다. 실제 직전 저장 구간 삭제·열린 후보 취소는 ⑤ 저장 구간 조립/T60의 책임이며, 이 구현은 신호만 제공한다.
2. `command`: 공조·내비·음량·미디어·전화 명령을 전체 문자열 일치로 찾는다. 호출어만 있는 줄도 명령이다. 호출어 뒤의 알 수 없는 명령은 설정된 명령형 종결 조건을 충족할 때만 잡는다. 단어 하나인 “저장”, “지워”, “꺼”만으로 명령이나 거부를 추정하지 않는다.
3. `external`: 거리와 방향을 갖춘 내비 안내, 고정 안내 문형, 청취자/이름+사연·신청곡이라는 방송 문형만 텍스트 규칙으로 잡는다. 통화·영상·노래의 일반 발화는 글만으로 판별하지 않는다.
4. `command`와 `external`이 잡힌 줄의 합집합이 **정규화 후 비어 있지 않은 입력 줄의 50%를 초과**하면 묶음을 막는다. 정확히 절반이면 해당 줄만 빼고 대화 모델로 보낸다. 따라서 일반 대화 네 줄 사이의 명령 한 줄은 그 줄만 제거한다. 명령·내비가 섞여도 합집합으로 계산한다. 줄 길이·음성 재생 시간에 따른 과반 판정은 아니다.
5. 공백·문장부호 제거, Hangul 받침 제거 사본 비교를 병행한다. 6자 이상 거부 리터럴에 한해 짧은 전체 후보와의 편집 거리 1도 허용한다. 명령·방송에는 일반 편집 거리를 적용하지 않는다. 받침 제거는 모든 받침을 접기 때문에 뜻이 다른 말을 같게 만들 위험이 있다.
6. 단일 줄부터 최대 연속 3줄을 검사하고, 이어 붙인 후보는 128자 이내로 제한한다. 빈 줄을 넘어 연결하지 않는다. 먼저 잡힌 명령의 이웃 대화까지 함께 제거하지 않도록 겹치는 큰 후보의 명령 매칭은 생략한다. 거부는 겹치는 후보도 계속 검사한다. 줄 경계가 없어도 거부의 부분 문자열 검색은 작동한다. 명령과 대화가 한 줄에 합쳐진 경우에는 명령 전체 일치가 실패할 수 있다.

논리 규칙 수는 **68개**다: 거부 정규식 6 + 거부 리터럴 48 + 명령 정규식 7 + 외부 정규식 4 + 호출어 3. 원본/받침 제거 사본의 중복 컴파일은 별도 규칙으로 세지 않는다. 공통 호출어 종결 제약은 설정값이다. 매칭 코어는 Python 표준 라이브러리와 공통 정규화만 사용한다.

### 호출어와 앱 신호

`DESIGN.md`·`rubric.md`에 제품 호출어는 지정돼 있지 않았다. `test/stt/story-dialogues.md`, `test/stt/tools/train-story-probe.py` 등의 **합성 예시**에 “글레오”가 있다. 기본 설정은 “글레오”, “헤이 글레오”, “헤이 플레오스”다. 뒤의 두 개는 교체 가능한 예시 설정이며 실제 제품 호출어로 검증하지 않았다. `PolicyGate(wake_words=[...])`로 교체하거나 빈 목록으로 호출어 매칭을 끌 수 있다. 외부 웹이나 실제 전사에서 호출어를 수집하지 않았다.

`AppSignals(playback_active=None, external_audio_dominant=None)`은 앱 연결 자리다. `playback_active=True`만으로 가족 대화를 차단하지 않는다. 앱이 **그 묶음 전체에서 외부 오디오가 대부분이라는 별도 증거**를 제공한 `external_audio_dominant=True`일 때만 전체 차단한다. 상태를 모르면 `None`으로 둔다. 기기 API 연결이나 신호 추론은 구현하지 않았으며, 이 경로는 단위 테스트로만 확인했다. 미디어 재생 중이라는 사실과 외부 소리가 묶음의 대부분이라는 사실은 같지 않다.

## 시험 묶음

시드 56. 기본 표현을 dev/held-out으로 먼저 나눈 뒤, 원문과 모든 열화·혼합 버전을 같은 분할에 유지했다. dev 거부 48개는 규칙 리터럴을 사용하고, held-out 거부 24개는 그 목록과 중복되지 않는 새 조합·바꿔 말하기다. 명령은 각 분할 16개, 외부 문형은 각 12개다. 정규화·공백 제거 후 원문 중복이 없는지도 테스트한다.

이는 **사람이 따로 수집한 비공개 블라인드 시험이 아니라 작성자가 만든 표현 분할**이다. 어휘·문형 계열은 공유한다. 규칙은 dev 오류를 보고 수정한 뒤 첫 held-out 평가 전에 고정했으며, held-out 결과를 이용한 규칙 추가·수정은 하지 않았다. 고정 해시는 `.local/policy/rules-frozen.json`에 남겼다.

각 기본 표현에 원문 1개 + 공백·문장부호를 없애고 두 줄로 나눈 버전 1개 + 받침 하나를 바꾼 버전 1개 + `synth.degrade.degrade(style="pleos")` 수준 1·2 각각 네 번, 총 **11개 버전**을 생성한다. 별도 실제 프로필 파일을 로드하지 않고 `DEFAULT_PROFILE` 정적 휴리스틱을 사용한다. 단어 삭제·단어 치환·짧은 줄 나누기를 그대로 적용하며, 정책 단어가 없어진 사례도 버리거나 재시도·재라벨하지 않는다. 받침 프로브는 실제 측정 오인식 확률이 아닌 별도 합성 스트레스다.

| 종류 | dev | held-out | 별도 정상 | 합계 |
| --- | ---: | ---: | ---: | ---: |
| 거부: 48/24 표현 × 11 | 528 | 264 | — | 792 |
| 명령: 16 표현 × 11 + 2개 명령 묶음 8개 | 184 | 184 | — | 368 |
| 외부: 12 표현 × 11 + 2개 안내·방송 묶음 6개 | 138 | 138 | — | 276 |
| 혼합: 가족 대화 4줄 사이에 명령 또는 그 조각 | 176 | 176 | — | 352 |
| 헷갈리는 정상: 직접 지은 가족 대화 32개 × 11 | — | — | 352 | 352 |
| T53 `blocks.jsonl` 파일 전체, 무선별 | — | — | 2,978 | 2,978 |
| 전체 | 1,026 | 762 | 3,330 | **5,118** |

새 생성 파일에는 2,140묶음이 있고, 평가는 기존 T53 2,978묶음을 읽어 합친다. T53은 `keep/none` 라벨과 무관하게 전부 정상 대화 묶음으로 평가했다. 파일명이나 카드 목표 수를 보고 3,000개로 간주하지 않았다. 정상 추가 시험에는 지우개 찾기, 사진 저장 확인, 가족에게 불 끄기 부탁, 그림 지우기, 녹음 수업 이야기, 내비 안내를 화제로 삼는 대화 등이 있다. 외부 음성 앱 신호는 이 텍스트 평가에 넣지 않았다.

## 실측 결과

차단율은 해당 정책 묶음 중 `block`이 나온 비율이다. 일반 대화 오차단율은 대화 묶음 중 `block`이 나온 비율이다. 줄 제거 정확도는 예상 제거 인덱스 집합과 실제 집합이 완전히 일치한 묶음 비율이며, 묶음 차단 여부와 구분한다.

| 정책 | dev 차단 / 전체 | dev 차단율 | held-out 차단 / 전체 | held-out 차단율 |
| --- | ---: | ---: | ---: | ---: |
| optout | 416 / 528 | 78.79% | 189 / 264 | 71.59% |
| command | 143 / 184 | 77.72% | 134 / 184 | 72.83% |
| external | 111 / 138 | 80.43% | 104 / 138 | 75.36% |
| 정책 전체 | **670 / 850** | **78.82%** | **427 / 586** | **72.87%** |

정책 전체 합산은 1,097 / 1,436 = 76.39%다. DESIGN §10의 기록 거부+명령만 따로 합쳐도 dev 559 / 712 = 78.51%, held-out 323 / 448 = 72.10%여서 기준 미달이다. 거부를 탐지해 차단한 사례는 모두 소급 삭제 신호가 함께 나왔다. 놓친 거부는 소급 삭제도 요청하지 못했다.

| 입력 변형별 정책 차단 | dev | held-out |
| --- | ---: | ---: |
| 원문 | 76 / 76 = 100.00% | 51 / 52 = 98.08% |
| 무공백·문장부호 제거 + 두 줄 분할 | 76 / 76 = 100.00% | 51 / 52 = 98.08% |
| 받침 하나 변형 | 76 / 76 = 100.00% | 51 / 52 = 98.08% |

위 단순 변형 성적만으로 전체 기준을 통과했다고 하지 않는다. 전체 분할을 합친 수준 0(원문·분할·쌍)은 281 / 284 = 98.94%, 수준 1(받침 프로브 포함)은 497 / 640 = 77.66%, 수준 2는 319 / 512 = 62.30%다. 같은 원문의 여러 열화 버전이라 독립 실제 표본으로 간주할 수 없다.

| 일반·혼합 시험 | dev | held-out 또는 별도 전체 |
| --- | ---: | ---: |
| T53 대화 묶음 오차단 | — | 0 / 2,978 = **0.00%** |
| 헷갈리는 정상 대화 묶음 오차단 | — | 0 / 352 = **0.00%** |
| 헷갈리는 정상에서 원치 않는 줄 제거 | — | 0 / 352 = 0.00% |
| 혼합 묶음 오차단 | 0 / 176 = **0.00%** | 0 / 176 = **0.00%** |
| 혼합 제거 인덱스 완전 일치 | 135 / 176 = **76.70%** | 127 / 176 = **72.16%** |
| 혼합 명령 조각 줄 정밀도 | 161 / 161 = 100.00% | 151 / 151 = 100.00% |
| 혼합 명령 조각 줄 재현율 | 161 / 203 = 79.31% | 151 / 203 = 74.38% |

혼합 합산 완전 일치는 262 / 352 = 74.43%다. 명령이 남아 모델로 넘어간 실패를 “묶음 오차단 0”에 숨기지 않는다.

T53은 299 / 2,978묶음에서 일부 줄(합계 365줄)을 제거했지만 묶음 전체는 모두 허용했다. 이유별 묶음 수는 `external.navigation` 271, `external.nav_notice` 58, `command.media` 1이며 중복될 수 있다. T53에는 합성 생성기가 삽입한 내비 줄도 있어 이 365줄을 전부 오제거라고 해석할 수 없다. T53에 줄별 정책 정답이 없으므로 **T53 줄 제거 정확도는 미검증**이다. 원문을 문서나 예측 파일에 복사하지 않았다.

## 실패 유형과 남은 한계

아래 예시는 실패 유형을 설명하려고 새로 지은 문장이다. 실제 전사 예시는 없다.

- **정책 단서 소실**: “기록을 멈춰 줘”에서 “멈춰 줘”만 남거나 “여행 기록”만 남으면 기록 거부인지 다른 부탁인지 글만으로 복구할 수 없다. 합성 열화에서도 이런 오류가 남았다. 정책 단어가 사라진 사례를 분모에서 제외하지 않았다.
- **새 명령형 어미·새 목적지**: “에어컨 켜 주실래요”, “작은 도서관으로 경로를 잡아 줘”처럼 데이터에 없는 어미·장소·동사 결합은 빠질 수 있다. 이는 정보 소실과 별개의 규칙 커버리지 부족이다. held-out 원문도 1건 놓쳤다.
- **줄 단위 과반의 경계**: 명령 두 줄 중 한 줄만 잡히면 절반이므로 묶음을 허용한다. 짧은 명령이 여러 줄로 쪼개지거나 긴 가족 발화가 한 줄로 합쳐지면 음성 시간 비중과 어긋난다. 최대 3줄보다 긴 조각 연결, 한 줄 안의 대화+명령도 남은 과제다.
- **인용·설명과 실제 거부**: “그 인물이 녹음하지 말자고 했어”처럼 거부 표현을 인용한 대화도 거부 검색에 잡힐 수 있다. 무조건 거부로 취급하는 현재 사생활 우선 규칙의 한계이며 별도 인용 시험 수치는 없다.
- **외부 음성의 식별 불가**: 라디오의 평범한 대화, 통화 상대의 일상 문장, 영상 속 가족 목소리, 노래 가사는 글만으로 탑승자와 구별하지 못한다. 미디어 재생 중에도 가족이 대화하므로 재생 상태 하나로 모두 차단하지 않는다. 앱의 신뢰할 수 있는 구간별 신호·정책이 필요하다.
- **합성·실차 차이**: 정적 Pleos 오류 프로필은 실제 차량 평가를 대체하지 않는다. 짧은 표현 1개가 들어 있는 정책 묶음에 강한 삭제·치환이 적용되므로 본 시험 비중 자체도 운영 분포 추정이 아니다. 실제 차량 데이터, 마이크 겹침, 신호 지연, Kotlin 일치성은 검증하지 않았다.

전체 0.95 기준을 만족하려면 인식 단서가 남는 구간에서 규칙 범위를 보완하는 작업과, 단서가 사라지는 경우의 앱 신호·기록 거부 UI 보완을 분리해서 검증해야 한다. 이번 held-out은 후속 개발에서는 이미 본 자료로 취급하고, 새 표현 분할을 별도로 만들어야 한다.

## Kotlin 이식 시 주의점

1. `common/normalize-vectors.json`으로 NFKC·소문자·Unicode L/N 범주의 Python/Kotlin 일치를 먼저 검증한다. 공백 제거는 정책 매칭용으로만 적용하고, 남은 모델 줄의 순서와 `input_text` 계약을 유지한다.
2. `rules.json`을 그대로 버전 관리하고 SHA256을 비교한다. Python `search`/`fullmatch`는 Kotlin `containsMatchIn`/`matches`로 명확히 대응한다. 정규식에는 Python 전용 lookbehind·이름 그룹·라이브러리 퍼지 연산이 없다. 받침 접기는 한글 완성형 U+AC00..U+D7A3에만 적용하며, 동일 처리를 규칙 사본과 입력 사본에 적용한다.
3. 편집 거리 1의 한 글자는 Python Unicode 코드 포인트 기준이다. Kotlin의 UTF-16 `Char` 순회와 보조 평면 문자의 차이를 확인한다. 현재 한국어 프로브가 BMP에 있다는 이유로 일반 입력까지 같다고 가정하지 않는다.
4. 빈 줄 포함 원본 인덱스, 비어 있지 않은 줄 분모, 엄격한 `> 0.5`, 중복 제거, 작은 후보 우선, 거부의 겹친 후보 재검사, 최대 3줄·128자 제한을 그대로 이식한다. 룰은 블록 간 상태를 보관하지 않는다.
5. `allow`일 때만 제거 후 남은 줄을 ④에 넘긴다. **자막만 지우고 대응 명령 음성을 그대로 저장하면 정책 준수가 아니다.** T59/T60에서 원본 줄 시각에 따라 오디오 제외 구간을 연결하고, 문맥·화자가 합쳐져 정확한 분리가 불가능한 경우의 저장 정책도 정해야 한다.
6. `retro_delete=True`는 현재 후보 취소와 **직전 저장 구간** 삭제를 원자적으로 연결한다. 모든 과거 기록 삭제로 확대하지 않는다. 재전송·재판정에도 동일 구간을 두 번 잘못 삭제하지 않도록 저장 구간 ID와 처리 상태를 앱이 관리한다.
7. 앱 신호는 `Boolean?`의 모름/참/거짓을 구분하고 해당 묶음의 시간 범위와 지연을 확인한다. 재생 중이라는 값만으로 `external_audio_dominant`를 만들지 않는다. 입력 원문을 로그·예외·분석 이벤트로 보내지 않는다.
8. `.local/policy/cases.jsonl`의 합성 입력과 `predictions.jsonl`의 정답·예측을 이식 대조에 사용할 수 있다. PC 시간 수치를 AVD/실차 수치로 대체하지 말고 별도로 측정한다.

## 완료 상태

구현·합성 생성·실제 평가·단위 테스트·문서 작성을 수행했다. **T56의 차단율 0.95 완료 기준은 미달**이다. 실제 차량 검증·앱 신호 연결·소급 삭제 실행·오디오 구간 제외·Kotlin 이식은 이 작업에서 구현하거나 검증하지 않았다.
