# T48 — 차 안 소리 사건 구분 시험

## 구현과 실행

`model-create/demo/sound/`에 모델 교체용 인터페이스, AST 구현, 평가 CLI를 추가했다. 기존 `demo/acoustic.py`의 AST 로더를 `offline=True`로 호출하고 PyAV 디코더를 그대로 재사용한다. AST 외 모델이나 외부 다운로드 코드는 실행하지 않는다. 네트워크·새 패키지·커밋 없이 실행했다.

- `core.py`: `SoundModel.score_window(waveform, rate)`를 구현하면 공통 창 처리와 그룹 집계를 재사용한다. `score_windows(waveform, rate)`는 `{AudioSet 라벨 이름: 창들의 최대 확률}`을 반환하고, `summarize`는 그룹별 max/mean을 함께 반환한다.
- `model.py`: 로컬 AST의 527개 라벨 sigmoid 확률을 사용한다. GPU가 있으면 GPU, 없으면 CPU를 선택한다. CPU 벤치마크에서는 모델을 CPU로 옮기고 PyTorch 스레드를 1개로 고정한 뒤 복원한다.
- `run.py`: 시험 A/B/C, 배경 보정·평가 분리, CPU 속도 측정 및 결과 파일 생성을 담당한다. 실패한 파일을 조용히 제외하지 않고 실행을 실패 처리한다. 예외의 원문이나 전사를 로그에 출력하지 않는다.
- `tests/test_sound.py`: 실제 가중치 없이 합성 PCM·가짜 점수로 시험한다. SNR 전력비, 공통 peak 정규화, 창 분할, 그룹 매핑, 없는 별칭, max/mean, 문턱값·동률·검출 분모·혼동 행렬·AUROC, 오프라인 AST 어댑터, CLI·마지막 판정 적용·전사 비출력·시드 재현성을 검증한다.

PowerShell에서 전체 재실행:

```powershell
Set-Location C:\github\drive-diary\talk-rec\model-create
.\.venv\Scripts\python.exe -m demo.sound.run --out .local/demo/sound/t48-full
```

기본값은 `--seed 48 --limit 0 --background-windows 200 --benchmark-repeats 5`이다. `--limit`은 Nonspeech7k의 **클래스당** 상한이며, 시험 C는 항상 사람 판정이 있는 모든 표본을 처리한다. 짧은 확인용 명령:

```powershell
.\.venv\Scripts\python.exe -m demo.sound.run --out .local/demo/sound/t48-limit20 --limit 20
```

검증 명령 및 관측 결과:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_sound.py tests/test_demo_acoustic.py --basetemp .local/pytest-t48 -p no:cacheprovider -q
```

**45 passed**. 새로운 테스트 21개와 기존 acoustic 회귀 테스트 24개가 통과했다. pytest 캐시를 끄고 지정한 임시 경로를 사용했다.

출력은 지정한 폴더의 `results.json`(수치·설정·명시적 id·재계산용 점수와 구간), `report.md`(표), `scores.jsonl`(실제 클립의 id/origin/verdict/groups별 max·mean)이다. 원본 전사·리뷰 코멘트를 복사하지 않는다. 아래 수치는 축소 실행이 아닌 `t48-full`의 실제 전체 실행 결과다.

## 평가 정의

- 16 kHz mono, 10초 창, 5초 hop. 짧으면 그대로 한 창으로 처리하며, 끝부분은 마지막 부분 창으로 덮는다. 특징 추출기의 기본 padding을 사용한다. 그룹 점수는 구성 라벨의 최댓값이며, 클립 max/mean은 창별 **그룹 점수**의 최댓값/동일 가중 평균이다. mean은 겹침을 보정한 시간 평균이 아니다.
- 모델 config의 실제 라벨 이름만 선택하고 없는 별칭은 건너뛴다. `results.json`에 실제 매핑과 누락 목록을 기록한다. 이번 AST 캐시는 요청한 별칭이 모두 있었다.
- `laugh`: Laughter / Baby laughter / Giggle / Snicker / Belly laugh / Chuckle, chortle.
- `shout`: Shout / Yell / Screaming / Children shouting / Bellow / Whoop / Battle cry.
- `cry`: Crying, sobbing / Baby cry, infant cry / Whimper / Wail, moan.
- `sing`: Singing / Child singing / Humming / Chant. `speech`: Speech / Child speech, kid speaking / Conversation.
- 정답은 `laugh→laugh`, `screaming→shout`, `crying→cry`. 강제 3종 분류는 세 그룹 원점수의 argmax다. 쌍별 AUROC는 해당 두 정답 클래스만 골라 첫 그룹 점수−둘째 그룹 점수를 사용한다.
- 최신 판정이 `none`인 실제 클립 20개를 시드로 섞어 보정 10개/평가 10개로 분할한다. 두 분할의 클립 id는 겹치지 않는다. 보정·평가 각각 200구간을 뽑고, 구간 길이는 대상 사건의 실제 WAV 길이 분포에서 뽑는다. 배경이 사건보다 짧으면 늘려 붙이지 않는다. `none`은 음향 무사건 라벨이 아니라 장면 저장 판정이다.
- 사건마다 평가 분할의 배경 클립과 시작점을 무작위로 하나 고른다. 같은 사건의 네 SNR에는 동일 구간을 쓴다. `P=mean(x²)`, 사건 배율 `sqrt(P_background × 10^(SNR/10) / P_event)`로 섞고, 합의 peak가 1을 넘으면 두 성분에 같은 배율을 적용해 SNR을 보존한다. 전력은 무음 부분을 포함한 구간 전체 기준이다. 무음 성분은 SNR 정의가 불가능하므로 오류 처리한다.
- 각 그룹의 보정 점수 순서통계량으로 경험적 FPR이 최대 5%가 되게 문턱값을 정한다. `score > threshold`일 때만 검출하므로 동률은 음성이다. 보정 표본 200개에서는 각 그룹 10개가 초과했다. 평가 배경의 FPR은 별도로 측정한다. 같은 문턱값을 clean 및 모든 SNR에 사용한다.
- 핵심 검출 표의 ‘해당 그룹 검출률’은 진짜 사건 그룹의 문턱값을 넘은 비율이다. ‘사건 하나 이상’은 세 대상 그룹 중 하나라도 문턱값을 넘은 비율이다. 검출 후 명명은 문턱값을 넘은 대상 그룹 중 원점수 최대로 한다. 오분류·양방향 오인의 분모는 **그 실제 클래스 중 사건 하나 이상 검출된 수**이며, 미검출은 분모에서 제외한다. `results.json`에는 reject 열을 포함한 혼동 행렬도 있다.
- 기타 네 클래스에는 진짜 세 사건이 없다고 보고 같은 문턱값에서 오경보를 계산한다. 노래 정답은 없으므로 노래 검출률을 평가했다고 해석하지 않는다.
- C는 표본 65개와 최신 판정의 교집합 36개 전체다. `story=8, moment=7, none=20, unsure=1`. 요약에는 unsure를 포함하고, 이진 AUROC에서는 제외한다. moment 대 나머지는 moment 대 story/none이며, keep 대 none은 story/moment 대 none이다. `laugh_or_sing`은 클립 laugh max와 sing max의 최댓값이다.
- CPU 벤치마크는 10초 합성 사인파 한 창, warmup 1회 뒤 5회 중앙값이다. 특징 추출·추론·확률 변환을 포함하고 모델 로딩·오디오 디코딩은 제외한다. 출력의 parameter bytes는 float32 파라미터의 메모리 크기이며 배포 파일 전체나 실행 peak RAM은 아니다.

## 데이터와 해석 범위

Nonspeech7k test의 WAV 725개를 모두 사용했다: breath 160, cough 70, crying 205, laugh 140, screaming 70, sneeze 30, yawm 50. [Zenodo 10.5281/zenodo.6967442](https://doi.org/10.5281/zenodo.6967442), **CC BY 4.0**. 저자·원본 음원의 출처 정보는 원본 배포와 CSV를 따른다. 원본은 읽기 전용으로 두고 평가 중 메모리에서만 차 안 배경과 혼합했다. 혼합 음원을 배포하지 않는다.

모델은 [MIT/ast-finetuned-audioset-10-10-0.4593](https://huggingface.co/MIT/ast-finetuned-audioset-10-10-0.4593), AudioSet 527 라벨이다. 이번 작업은 기존 로컬 캐시만 읽었다. 실제 차 안 클립과 사람 판정은 프로젝트 로컬 자료로, 별도 공개 재배포 권한을 가정하지 않는다.

Nonspeech7k는 따로 녹음된 깨끗한 소리라 실제 차 안의 큰 웃음·고함과 다르다. 합성 혼합은 차량 잔향·마이크·발화 중첩·동작 소음의 상호작용을 재현하지 않는다. 원본 `File_ID`가 같은 변형과 같은 배경 클립의 여러 구간은 독립 표본이 아니다. 클립 id는 분리했지만 같은 원본 영상이 두 분할에 걸칠 수 있으므로 신뢰구간이나 일반화 성능을 주장하지 않는다.

배경에 이미 웃음·울음·노래가 섞였을 수 있다. 그룹별 5% 보정은 세 사건 중 하나라도 잡는 오경보율 5%를 뜻하지 않으며, 별도 배경의 5%를 보장하지 않는다. 보정 구간은 사건에 맞춘 약 0.5–4초이고, 90초 묶음의 창 max는 오경보 기회를 늘린다. 실제 부정 장면(울음·고함)의 음향 정답 데이터가 없어 **울음·고함 점수로 저장 취소하는 정책은 아직 검증되지 않았다**. C는 특히 작은 표본이며 서로 다른 origin과 판정 선택 편향이 있다. AST의 약 346 MB 파라미터는 차량 탑재에 큰 부담이므로 큰 모델의 참고 상한으로만 쓴다.

## 관측 결과의 의미

전체 실행은 GPU(NVIDIA GeForce RTX 5060 Ti)에서 **193.6초**에 완료했다. A는 725개, B는 동일 725개 × 4 SNR, 별도 배경 400구간, C는 판정된 실제 클립 36개를 처리했다. 아래 결과의 대상 사건 수는 laugh 140 / screaming 70 / crying 205, 총 415개다.

- 깨끗한 소리의 강제 3종 분류 정확도는 **92.3%**, laugh–shout 쌍별 AUROC는 **0.9986**이었다. 이 조건에서는 웃음과 비명의 구분이 강했다.
- 그룹별 배경 오경보 5% 보정 문턱값에서 **0 dB**의 해당 그룹 검출률은 웃음 **73.6%**, 비명 **88.6%**, 울음 **72.2%**였다. **−5 dB**에서는 각각 **66.4% / 82.9% / 67.3%**로 내려갔다. 강제 argmax 정확도와 문턱값 검출률은 서로 다른 지표다.
- 검출된 웃음을 비명으로 부른 비율은 0 dB **3/109 = 2.8%**, −5 dB **7/102 = 6.9%**였다. 검출된 비명을 웃음으로 부른 비율은 각각 **1/64 = 1.6%**, **1/60 = 1.7%**였다. 실제 분모는 원래 클래스 전체가 아닌 ‘사건 하나 이상 검출’된 수다.
- 평가 전용 배경의 오경보율은 laugh **3.5%**, shout **5.0%**, cry **3.0%**였다. 보정 표본의 각 5.0%와 구분해야 한다.
- C에서 max(laugh,sing)의 AUROC는 moment 대 나머지 **0.4898**, keep 대 none **0.5367**이었다. 이 작은 실제 표본에서는 웃음·노래 점수 하나로 저장할 장면을 잘 가른다는 근거가 없었다. A/B의 음향 분류 성능을 장면 선택 효용으로 해석하면 안 된다.
- 파라미터 **86,594,063개**, float32 파라미터 **346.4 MB**, CPU 1스레드 10초 창 **2,478.9 ms**(5회 중앙값)였다. 이는 특징 추출을 포함한 측정이며 로딩·디코딩은 제외한다.

재계산 검증에서 저장된 모든 A/B 예측으로 scikit-learn의 혼동 행렬·정확도를 다시 계산해 일치를 확인했다. 조건별 725개, 대상 415개, 기타 310개, C의 고유 id 36개, 배경 분할 id 비중복, 보정 FPR 최대 5%도 확인했다. 아래 표는 `results.json`에서 생성한 `report.md`의 전체 수치를 그대로 옮겼다.

## T48b — 작은 모델(EfficientAT) 비교

차에 올릴 수 있는 크기의 AudioSet 분류기로 같은 시험을 반복했다. EfficientAT(MIT 라이선스)의 `mn04`(약 98만 파라미터)와 `mn10`(약 488만 파라미터)이다. 외부 코드라서 연결 코드(`demo/sound/efficientat.py`)만 작성했고, 실행은 사람이 직접 했다. 가중치는 받아 둔 로컬 파일을 `weights_only=True`로 읽고, 그 프로젝트의 내려받기 경로는 쓰지 않는다. 입력은 16 kHz → 32 kHz 재표본화, 128 mel, 10초보다 짧으면 무음으로 10초까지 채운다(아래 mn10 절 참고). 라벨 묶음·창·SNR·문턱값 보정은 AST와 같다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m demo.sound.run --model mn04 --out .local/demo/sound/mn04
.\.venv\Scripts\python.exe -X utf8 -B -m demo.sound.run --model mn10 --out .local/demo/sound/mn10
```

두 실행 모두 GPU, 10초 채움 조건이며 모든 라벨이 포화된 행은 0개다. 결과는 `.local/demo/sound/mn04`, `mn10`의 `report.md`·`results.json`.

| CPU 1스레드 10초 창 (특징 추출 포함) | 2,468 ms | 47 ms | 37 ms |

- **mn10은 웃음·비명·울음 구분에서 AST와 같은 수준이다.** 크기는 1/18, CPU 시간은 1/50이다. 차 안 소리가 더 큰 −5 dB에서도 웃음과 비명을 거의 헷갈리지 않는다(AUROC 0.985). 사용자가 물은 "고함과 큰 웃음을 구분할 수 있나"에는, 따로 녹음된 소리를 차 안 소리에 섞은 조건에서는 **작은 모델로도 가능하다**가 답이다.
- **크기·속도는 차에 올릴 수 있다.** mn10의 10초 창을 5초마다 보면 PC 한 코어의 약 1%다. 차량 CPU에서는 재지 않았다.
- **약점은 사건이 아닌 소리의 오경보다.** mn10은 차 안 소리가 클수록 숨·기침·하품을 사건으로 잡는 비율이 AST보다 높다(최대 35.5%). 하품은 세 모델 모두 절반 가까이 울음으로 잡는다. 울음 점수로 저장을 취소하면 정상 장면이 지워질 수 있다.
- **mn04는 0 dB 이하에서 비명 검출이 크게 떨어지고, 기침을 절반 가까이 울음으로 잡는다.** 후보에서 mn10보다 뒤에 둔다.
- **실제 클립에서는 세 모델 모두 신호가 없다.** 웃음·노래 점수가 사람 판정과 무관하다(AUROC 약 0.4–0.55, 35개 소표본). 소리로 "남길 장면" 점수를 올리는 근거는 여전히 없다.

### mn10: 짧은 입력에서 출력 포화 (수정 완료)

첫 실행(GPU)과 CPU 재실행 모두에서 862개 행이 모든 라벨 1.0으로 출력되었다. 두 장치 결과가 같으므로 GPU 문제가 아니다. 포화된 입력은 모두 약 2초 미만이었다(깨끗한 소리 0.52–2.04초, 배경 구간 0.63–1.83초). 정상 입력은 1.6초 이상이었다. 실제 10초 창 점수는 정상이었다. 당시 연결 코드는 1초 미만만 1초로 채웠다.

그래서 문턱값이 전부 1.0이 되고 검출률이 0%로 나왔으며, 강제 분류 정확도 52.5%도 의미가 없다. 연결 코드를 고쳐 모든 입력을 무음으로 **10초**까지 채운다. AST의 특징 추출기도 10초(1024 프레임)로 채우므로 세 모델의 입력 조건이 같아진다. 모든 라벨이 동시에 포화하면 조용히 점수로 기록하지 않고 오류를 낸다. 위 표는 수정 후 두 모델을 다시 실행한 결과다. 앱에 넣을 때도 짧은 구간은 10초로 채워야 한다.

### 해석·출처

- Nonspeech7k는 별도 녹음된 소리라 실제 차 안 사건과 다르다. 합성 혼합은 실제 차의 잔향·마이크·동시발화를 재현하지 않는다.
- none은 장면 저장 판정이며 무사건 라벨이 아니다. 배경에 이미 웃음·노래 등이 있을 수 있다. 구간은 독립 표본이 아니며 같은 원본 영상이 두 분할에 걸칠 수 있다.
- 창 max는 긴 클립에서 오경보 기회가 증가한다. 짧은 사건 길이로 보정한 문턱값은 90초 묶음 FPR을 보장하지 않는다.
- 실제 울음·고함 장면의 정답 데이터가 없어 저장 취소 정책의 안전성을 입증할 수 없다. C는 소표본으로 일반화 금지.
- 노래는 이 데이터셋의 정답 클래스가 아니므로 A/B에서 노래 검출 성능은 검증하지 않는다.
- AST는 차량 탑재용 크기가 아니며 큰 모델의 참고 상한이다. AUROC는 운영 문턱값 성능과 다르다.
- Nonspeech7k: Zenodo DOI 10.5281/zenodo.6967442, CC BY 4.0. 사용한 test 분할을 평가 목적으로 혼합했다. 원본 CSV의 File_ID가 같은 변형은 독립 표본이 아니다.
- AST: MIT/ast-finetuned-audioset-10-10-0.4593 (AudioSet 527 labels), 로컬 캐시만 사용. 프로젝트 기존 AST 로더·PyAV 디코더 재사용.
- 전사 및 판정 코멘트를 출력하지 않는다. scores.jsonl에는 id/origin/verdict/그룹 max·mean만 기록한다.
