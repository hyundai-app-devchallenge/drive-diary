## 구현

- `train/v3/data.py`: 시험 코드의 `input_text`, 합성 읽기, 장면·pair 분할을 import한다. 합성과 실제의 입력 글 함수는 `demo.trial.data.input_text` 하나다. 라벨 구성과 paired 여부를 층화해 전체 장면·pair 단위로 부분표본을 고른다.
- `train/v3/models.py`: M0는 글자 1~3-gram TF-IDF(최대 100,000, sublinear TF)와 독립적인 이진/종류 로지스틱 회귀다. M1은 KoELECTRA-small-v3 + 이진/종류 head다. 텍스트 토큰만 사용한다. M1 손실은 BCE + 0.2×CE이며 학습 기본값을 변경하거나 실제 dev로 하이퍼파라미터·데이터 규모를 고르지 않았다. 최종 비교 규모는 전체 2,978장으로 미리 고정했다.
- `train/v3/run.py`: dev 전용 학습·평가, 숫자 체크포인트와 서명 확인 재개, 가중치 저장, 고정 seed 후보, 재현성 확인이다.
- `eval/v3/metrics.py`, `report.py`: 제약 문턱 선택, 영상별 LOSO, 시드 평균±표본 SD, 출처/묶음 bootstrap, 기준선, 한국어 보고서다.
- `eval/v3/__main__.py`: 숫자 보고서 재생성과 별도 `test --open-test` 명령이다. test는 고정 가중치 해시·문턱을 사용하며 재학습이나 문턱 선택이 없다. 접근 전 배타적인 시도 표식을 만들고 반복 실행을 거부한다. 실제 test 명령은 실행하지 않았다.
- `synth/curate.py`: 기존 dedup/sample을 보존하고 `strip-sounds`를 추가했다. 기존 v1·v2 학습·평가 파일은 수정하지 않았다.

## 문턱과 구간의 해석

전체 child_family dev에서 keep 재현율 0.85 이상인 문턱 중 none 특이도 최대를 고른다. 조건을 만족하는 문턱이 없으면 재현율 최대를 고른다. 동률 처리까지 코드에 고정했다. LOSO는 한 영상을 뺀 나머지 child_family dev로 문턱을 정해 뺀 영상에 적용한다. 참고 구성에는 주 집단에서 정한 문턱을 그대로 쓴다. unsure 제외도 포함 평가의 문턱을 고정한다.

표의 기본 형식은 **시드 3개 평균 ± 표본 SD [영상 cluster bootstrap 95% 구간]**이다. bootstrap은 고정 시드 55로 2,000회 수행하며 시드 평균을 통계량으로 쓴다. 출처가 중복되면 그 출처의 모든 묶음과 사용 초를 함께 중복한다. 클래스가 사라진 재표집은 그 지표에서만 제외하고 정의된 횟수를 JSON에 기록한다. 이 구간은 학습된 모델과 원래 문턱에 조건부이며 재학습·문턱 재추정 불확실성을 포함하지 않는다. 별도 묶음 bootstrap 표는 묶음만 복원 추출하고 원래 출처 사용 초를 고정한 보조 결과다.

## 소리 토큰 제거와 동일성 확인

T53 지름길 검사에서 moment 장면의 **22%**에 웃음 소리 글이 있었고 none은 **0.3%**였다. 합성 작성 습관만으로 라벨을 알아맞힐 수 있는 단서여서 합성 장면에서 웃음·울음 토큰을 제거한 `scenes-nolaugh.jsonl`을 열화한 자료로 학습했다. 실제 Pleos 전사에는 이 정리를 적용하지 않는다.

`strip-sounds`는 공백 단위 토큰 앞뒤의 `!~.,?…()[]{}`를 뗀 핵심이 2글자 이상이고 `^(?:푸|으)?(?:하|허|크|히|헤|깔|낄|키득|앙|ㅋ|ㅎ)+$`와 완전히 일치할 때만 토큰을 지운다. 빈 줄은 제외하고 나머지 장면·줄 메타데이터와 순서는 보존한다. 낱말 일부를 지우지 않는다. 생성 파일의 직렬화에는 기존 `write_jsonl`을 쓴다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m synth.curate strip-sounds --scenes .local/synth/t53/scenes.jsonl --out .local/synth/t53/scenes-strip-sounds-check.jsonl
```

위 명령을 실제로 실행하고 Python `read_bytes()` 비교로 기존 `scenes-nolaugh.jsonl`과 **바이트 단위 일치**를 확인했다. 두 파일 SHA-256은 모두 `a51f89b0e6c8b1504c9c484b134d852059668948d2730fb6fef05c6245541a2c`다. 기존 사용자의 결과는 덮어쓰지 않았다.


## 개인정보 처리 사고 기록

초기 입력 스키마 점검에서 `eval.real.load_labels`의 반환형을 잘못 가정해 실제 전사 일부와 사람 코멘트가 도구 출력에 노출됐다. 이 요구 사항 위반은 되돌릴 수 없다. 이후 실제 자료는 개수·필드 이름·id·수치만 출력하도록 바꿨고, 전사나 코멘트를 코드·산출물 보고서·이 문서·저장소 파일로 복사하지 않았다. CLI 예외는 형식명과 코드 위치만 내도록 구현·가짜 입력 검사했다.
