## 묶음 규칙과 숫자 단서

원본 source 필드로 발화를 모아 `(start, utt)`로 정렬한다. 원래 utt 인덱스를 저장하며 중복 발화 id는 실패시킨다. 다음 발화와의 간격이 silence 이상이거나, 다음 발화를 넣을 span이 max-seconds를 초과하거나, 이미 max-turns개이면 현재 묶음을 닫는다. 길이가 정확히 90초이면 허용하고 정확히 20초 침묵이면 닫는다. 단일 긴 발화는 쪼개지 않는다. span의 end는 묶음 내 최대 end다.

id는 source별 0부터 시작하는 `{source}@{block}`이다. prefix는 직전 묶음의 마지막 두 원본 턴이며, 첫 묶음이거나 간격이 60초보다 클 때 비운다. 정확히 60초면 남긴다. gap_before는 직전 묶음의 최대 end가 아니라 **마지막 발화의 end**에서 다음 묶음 첫 start까지다. 첫 묶음은 null이다.

| 단서 | 계산식 |
| --- | --- |
| n_turns | 원래 발화 수 |
| seconds | 최대 end − 첫 start |
| speech_share | 발화 길이 합 / span. span이 0이면 0 |
| median_gap | 내부 인접 발화의 다음 start − 직전 end 중앙값. 한 턴이면 0 |
| gap_before | 원래 간격을 위쪽 600초에서 제한. null이면 600. 최상위 gap_before에는 원래 값/null 보존 |

겹치는 타임스탬프는 임의 보정하지 않는다. 따라서 speech_share는 1보다 클 수 있고 gap은 음수일 수 있다. 아래는 **중앙값 / p90 / p99 / 최댓값**이다. 분위수는 `(n-1)*p` 위치에서 선형 보간한다.


| 단서 | 기본 | 분석 |
| --- | --- | --- |
| n_turns | 11.50 / 12.00 / 12.00 / 12.00 | 9.00 / 12.00 / 12.00 / 12.00 |
| seconds | 72.22 / 87.44 / 89.02 / 89.03 | 76.75 / 87.86 / 89.82 / 89.99 |
| speech_share | 0.59 / 0.69 / 0.81 / 0.82 | 0.67 / 0.99 / 1.00 / 1.00 |
| median_gap | 2.00 / 4.13 / 10.09 / 11.24 | 1.78 / 4.32 / 12.31 / 19.80 |
| gap_before | 3.33 / 99.18 / 600.00 / 600.00 | 7.54 / 67.76 / 600.00 / 600.00 |


닫힌 원인은 상호 배타적으로 집계한다. 다음 발화가 있으면 침묵 → 길이 → 턴 수 순서로 먼저 맞는 조건을 closed_by에 기록하며, 다음 발화가 없으면 소스 끝으로 기록한다. 조건이 겹칠 때의 집계 규칙이고 분할 위치는 같다.

## 토큰 분포와 각 갈래 처리 횟수

`monologg/koelectra-small-v3-discriminator`를 `.local/hf`에서 local_files_only로 로드한다. 각 턴을 normalize한 뒤 특수 토큰 없이 인코딩한다. 입력 길이는 CLS 1개와 남은 모든 prefix·묶음 턴마다 내용+SEP 1개의 합이다. 본 묶음 턴과 그 SEP만 segment id 1이다. 아래는 **제한 전 길이**이며 prefix와 CLS/SEP를 포함한다.

갈래 횟수는 겹칠 수 있다. 분석에서 제거한 앞문맥은 총 201턴, 가운데 턴은 74턴이며 기본은 모두 0이다. 저장된 전사와 숫자 단서는 자르지 않는다.

순수 함수 `fit_tokens(prefix_token_lists, turn_token_lists, limit)`는 원본을 변경하지 않고 남긴 prefix/turn의 원래 인덱스, 불변 토큰 튜플과 제거·절단 정보를 반환한다. 오래된 앞문맥부터 제거하고, 그래도 넘으면 가운데 턴을 중심에서 바깥쪽으로 좌우 교대로 제거한다. 0부터의 인덱스로 6턴의 제거 순서는 2,3,1,4, 7턴은 3,2,4,1,5다. 양끝을 우선 보존하되 양끝 두 턴만으로도 한도를 넘으면 첫 턴을 버리고 최신 턴을 남긴다. 남은 한 턴도 길면 마지막 `limit-2`개 토큰만 남긴다. 실데이터에서는 마지막 두 갈래가 발생하지 않았다. limit 2는 CLS/SEP 사이 빈 내용을 허용하며, 그보다 작거나 정수가 아닌 예산 및 빈 본 묶음은 거절한다.

`model_input()`은 정규화·인코딩·fit·특수 토큰·segment·attention mask 조립을 제공한다. `--token-limit`을 바꾸면 처리 횟수와 over_limit은 해당 예산을 따르고, 320 초과율은 별도로 유지한다.

## 설정별 교환 관계: 권고 없는 관찰

길이 90초·12턴을 고정하고 침묵을 10→20→30초로 늘리면 시간당 묶음은 55.64→44.13→41.21개, 길이 중앙값은 46.60→76.75→79.67초다. 한 턴 비중은 14.73→7.12→4.09%, 320토큰 초과는 12.01→15.01→15.94%다. 더 긴 간격의 발화를 함께 보게 된다.

침묵 20초·12턴을 고정하고 길이를 60→90→120초로 늘리면 시간당 묶음은 58.22→44.13→40.09개, 길이 p90은 58.93→87.87→113.75초, 토큰 초과는 4.05→15.01→20.03%다. 한 묶음에서 더 긴 시간 흐름을 보게 되고 토큰 처리가 늘어난다.

침묵 20초·길이 90초에서 최대 턴을 8→12→16으로 늘리면 시간당 묶음은 53.95→44.13→42.72개, 길이 중앙값은 54.22→76.75→80.13초, 토큰 초과는 10.93→15.01→15.51%다. 턴 닫힘은 55.67→14.63→1.58%, 길이 닫힘은 11.76→45.55→57.29%다. 60초 제한에서는 12턴과 16턴 차이가 작다. 다른 조건이 먼저 닫기 때문이다.

전체 그리드에서 시간당 묶음은 32.28~71.19개, 토큰 초과는 3.00~26.78%다. 중앙값과 한 턴 비율이 모든 조합에서 단조롭게 변하지는 않는다. 앞 경계가 뒤 묶음의 시작과 prefix도 바꾸기 때문이다. 이 표는 분량과 입력 길이 변화만 보여 준다. 대화 품질이나 저장 가치의 우열은 판단하지 않으며 설정은 설계자가 결정한다.

## 검증 결과와 미충족 항목

T22 새 테스트 **386개 통과**, 기존 스키마와 windows 회귀를 함께 실행한 결과는 **706 passed**다. 정확히 20초/19.99초, 정확히 90초/초과, 12턴, 긴 단일 발화, 60초 문맥 컷, 손계산 단서, 사람 승인·Claude 배제·출력 보호, 4/5열·재시도, 모든 토큰 갈래의 남긴 인덱스, 120개 무작위 발화열 partition, 손상 출력 거절을 검사한다. CLI 테스트는 sweep이 선택 JSON 외 파일을 쓰거나 바꾸지 않는 것도 확인한다.

마지막 전체 pytest는 **1,253 passed / 9 failed / 51.42초**였다. 따라서 요청한 **전체 pytest 통과 조건은 미충족**이다. 실패는 모두 지정 영역 밖의 `tests/test_label.py`다. v2 프롬프트의 `{{BLOCKS}}`와 기존 `pipeline/label.py:159`의 `{{CLIP}}` 치환이 맞지 않아 렌더링·fake 응답·재시도·재개 테스트가 실패한다. T22에서 라벨러나 프롬프트를 수정하지 않았다.

실패 테스트: `test_exact_prompt_template_and_gaps`, `test_dirty_json_with_other_arrays_and_gap_precision`, `test_retry_feedback_then_success_and_failure_continues`, `test_resume_after_interruption_no_duplicates`, `test_changed_input_and_configuration_rejected`, `test_rate_limit_exit_and_resume`, `test_concurrency_separate_backends_and_unique_ids`, `test_main_dry_run_cli_fake_resume_and_run_tag`, `test_reserved_source_filename_does_not_overwrite_logs`.

초기에는 검토 콘솔 HTTP 테스트 2개도 AdGuard 응답 변형과 함께 실패했으나, 다른 작업 변경이 반영된 마지막 전체 실행에서는 사라졌다. 최종 실패 9개에 포함하지 않는다.

## 알아 둘 점

- 현재 기본 train/test는 0묶음이고 dev만 20묶음이다. 승인과 manifest status를 동시에 만족해야 한다. 승인 파일 갱신은 이 작업이 수행하지 않았다.
- `--allow-prescreened`는 분포 분석 전용이다. 기본 `.local/blocks` 경로를 거절하고 stats와 sweep JSON에 `prescreened_included: true`를 남긴다. 분석 JSON도 기본 블록 디렉터리 안에는 쓸 수 없다. 분석 결과를 라벨링·학습에 넘기면 안 된다.
- 매니페스트 split을 그대로 쓰고 채널 고정과 lowdensity test 전용 규칙을 검사한다. 해시를 다시 계산하거나 분할을 자동 수정하지 않는다. v1과 같이 downloaded 소스의 분할 이상은 승인 배제와 별개로 실패시킨다.
- 승인 파일은 호출마다 스냅샷을 읽는다. 빌드 뒤 승인·매니페스트·전사가 바뀌면 검사에서 누락/부적격 오류가 날 수 있어 재생성이 필요하다. 이번 실행에서도 확인했다.
- `--check`는 Transformers를 import하지 않고 오프라인으로 expected partition을 재구성한다. 저장된 stats의 닫기 설정을 사용하며 승인 모드는 stats와 같아야 한다. 고유 id·원래 utt 해석·원문·prefix·단서·닫기·누락·중복·적격성·채널 겹침을 검사하고 오류면 exit 1이다.
- JSONL과 stats 각각은 임시 파일 후 원자 교체하지만 디렉터리 전체가 하나의 트랜잭션은 아니다. 같은 출력 경로의 빌더를 동시에 실행하지 않고 빌드 완료 후 소비한다.
- 빈 분포는 분위수/최댓값 null, 비율 0이다. sweep은 기존 빌드 JSONL/stats를 변경하지 않는다.
