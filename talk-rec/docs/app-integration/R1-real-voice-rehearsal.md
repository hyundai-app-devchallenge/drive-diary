# R1 실제 음성 리허설 (2026-11-13)

Windows TTS 대신 실제 사람 목소리로 전체 흐름을 돌려 본 기록. 음성과 전사, DB 사본은 모두 `model-create/.local/real/v1/rehearsal/`에만 있다. 이 문서에는 전사 글과 제목을 적지 않는다.

## 쓴 음성
- dev 묶음의 아이·가족 영상 1개(`real-cast.tsv`에서 child_family)를 골랐다. Pleos용 PCM 조각 4개(각 90초)를 이어 붙이고 끝에 25초 무음을 넣어 6분 25초 파일을 만들었다.
- 시험용일 뿐 데모 음성은 아니다(데모에는 YouTube 평가 음성을 쓰지 않는다).

## 2. 저품질 전사에서 요약 품질 (dev 40묶음)
Pleos STT 전사(이미 `.local`에 있던 실제 영상 묶음 40개, 90초 단위)를 앱과 같은 형식(줄바꿈 연결)으로 중계 서버에 보냈다.

| 모델 | 성공 | 응답 시간 중앙값 | 메모 |
|---|---|---|---|
| gemini-3.8-flash-medium | 27/40 | 16.6초 | 실패 13건은 모두 아래 연결 끊김. 재시도 없이 돌렸다 |
| gemini-4-hydrogen-medium | 40/40 | 13.5초 | 끊김은 재시도로 넘김 |

Claude가 전사와 제목을 하나씩 대조했다(Flash 27건 기준).
- 약 20건은 대화의 중심 화제를 정확히 잡았다. 전사가 문장 단위로 깨져 있어도 반복되는 핵심 낱말을 잘 찾는다.
- 약 5건은 틀리지는 않았지만 막연하다(예: "~에 대해 나눈 이야기"). 입력 자체가 짧거나 잡음뿐인 묶음이다.
- 2건은 어긋났다. 거의 잡음뿐인 묶음에 내용을 지어 붙였고, 태그 하나가 맞지 않았다.
- Hydrogen은 같은 묶음에서 거의 같은 화제를 잡는다. 제목은 조금 더 문자 그대로이고 kind는 거의 다 story다. 품질 차이는 크지 않다.
- 공통 문제로 "가족 이야기" 태그가 지나치게 많다(Flash 27건 중 22건). 친구끼리 한 대화에도 붙는다. 태그 목록에 친구 관련 태그가 없어서다. 프롬프트의 태그 목록을 정할 때 함께 정해야 한다.
- 잡음뿐인 짧은 묶음은 판정 단계에서 걸러지는 것이 맞다. 요약 쪽에서 "내용 없음"을 돌려줄 길이 없어서, 지금은 무엇이든 제목을 만든다.

## 3. 로컬 연결 끊김 (원인 확인)
- 증상: 중계 서버는 200으로 응답했다고 로그를 남기는데, 클라이언트는 ConnectionResetError(앱에서는 "네트워크") 오류를 받는다.
- 아주 단순한 Python `http.server`에서도 20~40%가 끊겼다. curl과 PowerShell 클라이언트, 샌드박스 밖에서도 같았다. 즉 이 PC(Windows 11 26300)의 loopback 문제이고 우리 코드 문제가 아니다.
- 완화책: 중계 서버가 응답 뒤 half-close를 하고 클라이언트가 먼저 닫을 때까지 기다리게 했다(`SummaryServer.shutdown_request`). 시험에서 24/60이 2/60으로 줄었다.
- 앱의 SummaryWorker는 NETWORK 오류를 자동으로 재시도한다. 실제 기기는 HTTPS로 Gemini를 직접 부르므로 해당이 없다.

## 4. agy
- agy 1.5.7이 최신이다. Gemini 4 Carbon은 ADC/엔터프라이즈 로그인에서만 보여서 지금 계정으로는 쓸 수 없다.
- Gemini 4 Hydrogen(low/medium/high/xhigh)은 쓸 수 있다. 중계 서버는 low/medium/high만 인식한다.
- agy 실행 파일이 Codex 앱 패키지 폴더(`Packages\OpenAI.Codex_...\LocalCache\Local\agy`)에 깔려 있었다. Codex 안에서 설치해서 Windows가 경로를 바꾼 것이다. `%LOCALAPPDATA%\agy\bin\agy.exe`로 복사했고(PATH는 이미 여기를 가리킴), `pipeline/label.py`가 이 경로를 먼저 보게 바꿨다.

## 5. 태그 mix 방식 재시험 (I9a 반영 뒤, 같은 dev 40묶음, gemini-3.8-flash-medium)
분류 1개(고정 목록 13개)와 키워드 0~2개(LLM 선택)로 바꾼 뒤 같은 40묶음을 다시 돌렸다. 40/40 성공했다(중계 서버 끊김 완화와 클라이언트 재시도 덕분).

| | 예전(고정 목록 1~3개) | mix |
|---|---|---|
| "가족 이야기" 비율 | Flash 22/27, Hydrogen 대부분 | 분류로 5/40 |
| 분류 분포 | - | 운전·길 10, 아이의 하루 9, 가족 이야기 5, 놀이 4, 음식 3, 자연·풍경 3, 학교 2, 친구 이야기 2, 노래·웃음 1, 추억 1 |
| 키워드 개수 | - | 2개 19, 1개 16, 0개 5 |

Claude가 전사와 하나씩 대조했다.
- 키워드 대부분이 실제로 말한 구체적인 물건이나 활동이다. 묶음마다 서로 구별된다.
- 사람 이름(아이 이름 등)은 하나도 나오지 않았다.
- 친구끼리 나눈 대화가 처음으로 "친구 이야기"로 분류됐다.
- 약한 키워드도 있다. "카드", "소리", "물"처럼 너무 일반적인 말이 4~5건 나왔다. 출산처럼 건강과 맞닿은 말도 1건 나왔다(프롬프트상 민감 내용 금지와 경계).
- "운전·길"이 10건으로 가장 많다. 평가 자료가 운전 브이로그라 자연스럽다. 다만 영수증이나 카드 이야기처럼 내비 음성이 섞인 묶음까지 운전·길로 간 경우가 1~2건 있다.
- 거의 잡음뿐인 묶음은 키워드가 비거나(5건) 막연한 제목이 된다. 판정 단계에서 걸러야 할 몫이다.

## 발견한 문제
1. 다이어리의 대화 조각마다 "동반이 질문" 표시가 붙는다. 팀 앱 규칙이다(`V3Mappers.kt:227`, 녹음 시작 10분 안에 질문이 있었으면 질문에서 나온 이야기로 본다). 상시 기록에서는 여행 시작 질문 뒤 10분 안의 조각에 모두 붙는다. 대화 조각에는 이 규칙을 빼거나 기준을 줄일지 정해야 한다.
2. "이 순간 담기" 버튼은 여행의 기록 모드(ON)를 따른다. 그래서 캡처가 멈춘 상태에서도 보인다. 멈춤 상태에서는 숨기거나 누르면 다시 녹음하게 할지 정해야 한다.
3. "가족 이야기" 태그 남용, 친구 태그 없음(위 2절).
4. 실제 대화는 묶음이 90초 상한에서 끊긴다. 한 이야기가 여러 조각으로 나뉘어 제목이 비슷하게 반복된다(예: 같은 화제로 2개).
